## 1. 제품 개요

### 1.1 무엇인가

**모델터(modelter.com)** — 한국 상업용 부동산(CRE) 실무자를 위한 재무모델 빌더. 단일 HTML 파일 웹앱이며 설치·가입·빌드가 없습니다.

숫자를 입력하면 화면에서 IRR·DSCR 등 지표를 즉시 보여주고, **수식이 살아 있는 엑셀 파일**을 그 자리에서 생성합니다.

### 1.2 사용자

- 한국의 CRE 실무자 — 자산운용사·리츠·신탁사·PF 대주단·자문사의 딜 담당자
- 전형적 상황: **IM(투자설명서)이나 티저를 받은 직후**, 검토할 가치가 있는 딜인지 30분 안에 판단해야 함
- 대안: 회사 표준 엑셀 템플릿(있으면), 또는 처음부터 직접 만들기(보통 반나절~하루)

### 1.3 지원 딜 유형 (4종)

| 딜 유형 | 내용 | 엑셀 시트 수 | 예시 입력 항목 수 |
|---|---|---|---|
| **오피스 매입** (기본 화면) | 임대료·관리비 기반 NOI → 자본구조 → Exit | 13 | 19 |
| **물류 매입** | 오피스와 동일 구조, 물류 특성값 | 13 | 19 |
| **분양(개발·PF)** | 공동주택 분양 사업수지, 브릿지→본PF, 중도금 월별 엔진 | 6 | 35 |
| **리파이낸싱 비교** | 기존 대출 대비 신규 조건 비교 | 4 | 10 |

**자본구조 4단**: 선순위 → 중순위(메자닌, 현금이자/PIK 분기) → 보증금 승계 → 우선주 → 보통주

**"준비 중" 탭 (가짜 문)**: 호텔·리테일·임대주택·데이터센터 — 클릭하면 "관심 있음"만 익명 집계. 수요 검증용.

### 1.4 산출물 (이 도구가 만들어 내보내는 것)

| 산출물 | 이벤트명 | 성격 |
|---|---|---|
| 엑셀 다운로드 | `xlsx_download` | 주력. 수식이 살아 있음 |
| AI 프롬프트 복사 | `prompt_copy` | 결과를 LLM에 물어보기 위한 텍스트 |
| IC 원페이저 (인쇄) | `ic_ppt` | 투자심의용 1장 |
| 티저 요약 | `teaser` | 한 줄 보고 |
| 공유 링크 | `share_link` | URL 안에 상태 압축(#v=/#e=), 서버 저장 없음 |
| PDF 내보내기 | `pdf_export` | |
| PNG 카드 | `png_card` | |

### 1.5 핵심 약속 (변경 불가)

1. **화면 = 다운로드 엑셀** (파리티) — 화면 수치와 엑셀 수식이 동일한 계산식. CI가 11개 조합으로 강제.
2. **딜 데이터는 서버로 가지 않는다** — 계산·저장·공유 전부 브라우저 안에서.
3. **설치·가입·빌드 없음**.

## 2. 사업 목표와 지표 체계

### 2.1 북극성 (2026-08-15 고정)

> **한국에서 CRE 딜 검토를 시작할 때, 첫 숫자를 뽑는 기본 도구가 된다.**

- 검증 문장: 팀 안에서 **"이거 모델터로 돌려봤어?"**가 자연스럽게 나온다.
- 지향점: "많이 쓰이는 사이트"가 아니라 **특정 순간에 반드시 떠오르는 도구**.
- 그 순간: ① IM·티저를 받은 직후 ② 입찰·대주·내부 미팅 전 ③ 팀에 첫 검토 숫자를 올리기 전.
- **비목표**: 방문자 수만 늘리기, 기능 수 늘리기, 수요 게이트 전 새 딜 유형 만들기.

## 3. 계측 체계 — 무엇을 어떻게 재는가

### 3.1 수집 원칙 (완화 불가)

> **딜 데이터 서버 전송 금지.** 수집은 **이벤트명·딜 유형·기능 플래그·기기·유입 호스트**만.
> **수치·임차인명·개인식별정보는 절대 전송하지 않습니다.**

즉, "IRR이 몇 %였는지", "얼마짜리 딜인지"는 **알 수 없습니다**. 오직 "어떤 행동이 몇 번 일어났는가"만 압니다.

### 3.2 파이프라인

```
브라우저 → /e (Cloudflare Worker) → Analytics Engine (dataset: Modelter)
```

### 3.3 스키마

| 필드 | 내용 |
|---|---|
| `blob1` | 이벤트명 |
| `blob2` | 딜 유형 (office / logistics / dev / refi / hotel / retail / rental / datacenter) |
| `blob3` | 깊이 (quick / standard / deep) |
| `blob4` | 기기 (desktop / mobile / tablet) |
| `blob5` | 유입 호스트 (referrer의 호스트만) |
| `blob6` | 국가 |
| `blob7` | 활성 기능 플래그 (vac, hold, dep, pref, mezz, scen, rr …) |
| `blob8` | 민감도 축 |
| `blob9` | `src` — 자기 신고 채널 태그 (seo, sns, xlsx, ppt, png, share, imcheck, howto, dscr, pwa) |
| `blob10` | 봇 태그 (자동화 브라우저 감지 — 조회 시 기본 제외) |
| `blob11` | **`act` — 실사용 표식.** 이 세션이 자기 숫자를 직접 입력했는지 여부(0/1)만. **입력한 값 자체는 전송되지 않음** |
| `_sample_interval` | 표본 가중치. 합이 추정 실건수 |

### 3.4 퍼널 4단계 정의

| 단계 | 이벤트 | 발화 조건 |
|---|---|---|
| 방문 | `session` | 페이지 로드, 세션당 1회 |
| 딜 탭 클릭 | `deal_select` | **딜 탭 버튼을 눌렀을 때만** |
| 자기 숫자 입력 | `activate` | 신뢰 가능한 사용자 입력(`isTrusted`)이 발생. 세션당 1회 |
| 결과 | `computed` | 계산 결과 산출. 세션당 1회 |

### 3.5 `act` 플래그 (북극성 계측)

`activate`가 발화한 뒤의 모든 이벤트에 `act=1`을 실어 보냅니다. 이로써 **"예시를 구경하다 다운로드한 것"과 "자기 딜을 넣고 다운로드한 것"을 구분**합니다.

- 2026-07-26 배포. **이전 데이터는 `blob11=''`이라 소급 불가.**

## 5. 이 숫자를 읽을 때의 한계 — 반드시 감안할 것

1. **표본 가중치 기반 추정치.** Cloudflare Analytics Engine이 `_sample_interval`로 가중합을 냅니다. 절대값은 ±오차가 있습니다.
2. **세션 단위 조인 불가.** 모든 값은 **이벤트 총량**입니다. "이 세션이 A를 하고 그 다음 B를 했다"를 추적할 수 없습니다. 그래서 일부 채널에서 산출물 수가 방문 수를 넘습니다.
3. **`deal_select`는 탭 버튼 클릭에서만 발화.** 오피스가 기본 화면이라 오피스 전환율은 다른 딜과 같은 기준이 아닙니다.
4. **`act` 플래그는 2026-07-26 이후만 유효.** 소급 불가.
5. **수치·PII를 수집하지 않음.** 따라서 "어떤 값에서 막혔는지", "딜 규모가 얼마인지", "같은 사람이 재방문했는지"를 알 수 없습니다. 사용자 식별자가 없어 **코호트·리텐션 분석이 원천적으로 불가능**합니다.
6. **`src` 태그는 자기 신고.** 파일에서 클릭해 들어오면 referrer가 없어 URL 프래그먼트(`#src=`)에만 의존합니다.
7. **표본이 작습니다.** 일 방문 2~46, 일 입력 0~12. 하루 단위 등락은 대부분 노이즈로 봐야 합니다.

## 8. 제약 조건 (제안 시 반드시 지켜야 할 것)
