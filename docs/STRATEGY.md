## 0. 북극성 목표 (2026-08-15 고정)

> **한국에서 CRE 딜 검토를 시작할 때, 첫 숫자를 뽑는 기본 도구가 된다.**

- 검증 문장: 팀 안에서 **“이거 모델터로 돌려봤어?”**가 자연스럽게 나온다.
- 지향점: “많이 쓰이는 사이트”가 아니라 **특정 순간에 반드시 떠오르는 도구**다.
- 그 순간: ① IM·티저를 받은 직후 ② 입찰·대주·내부 미팅 전 ③ 팀에 첫 검토 숫자를 올리기 전.
- 비목표: 방문자 수만 늘리기, 이미 포화된 기능 수 늘리기, 수요 게이트 전 새 딜 유형 만들기.

**배포 전 기준선(2026-08-13, 최근 30일·봇 제외):** 방문 882 → 자기 숫자 입력 102(11.6%) → 결과 101,
산출물 272. `act` 계측이 가능한 구간의 실사용 산출물 119, 예시 산출물 69, 계측 이전 84.

**이번 실험(8월 15일 배포 후보):** 넓은 “기관급 모델을 누구나” 메시지를 “딜 받았으면, 모델터부터”로 좁히고,
첫 화면을 `IM·티저 → 첫 숫자 → 하방 → 팀 공유` 순서로 재구성한다. 새 공유 기능을 만들지 않고 기존 한 줄 보고·읽기 전용 링크를
1차 검토 결과 바로 아래에 노출한다. 공유 메뉴를 열기만 해도 산출물로 세던 오계측은 `handoff_open`(비산출물)로 분리하고,
실제 링크 생성·복사만 `share_link`로 유지한다.

**사전 판정(배포 후 14일):**

1. 활성화율은 **10% 이상 유지**한다(메시지 변경이 진입을 해치면 실패).
2. 자기 숫자를 넣은 세션의 `handoff_open`이 **10건 이상**, 실제 `share_link`가 **5건 이상**이면 팀 전달 동선의 발견 신호로 본다.
3. 첫 자기 딜 결과 시간 표본이 **20건 이상** 쌓이면, 페이지 진입 후 **15분 이내 70% 이상**을 “첫 숫자” 속도 약속의 지지 신호로 본다. 정확한 시간은 수집하지 않고 4개 구간만 센다. 표본 미달이면 판정하지 않는다.
4. `handoff_open`이 3건 미만이면 결과 바로 아래 노출은 철회하고, 공유·회수 추가 투자는 다시 중단한다.
5. 최종 질적 검증은 서로 다른 실무자 3명 이상에게서 “딜 검토 시작 때 열었다”는 자발적 설명을 받고,
   그중 1개 팀 이상에서 모델터 사용 여부를 묻는 표현이 실제로 반복되는 것이다. 유도 질문 답변은 증거로 세지 않는다.
6. 4주 뒤 주간 실사용 산출물(`act=1`)이 배포 직전 7일 기준선 대비 **30% 이상 증가**하면 북극성 선행지표 개선으로 채택한다.

질적 증거는 [`docs/NORTH_STAR_EVIDENCE.md`](NORTH_STAR_EVIDENCE.md)의 비유도 질문·익명 기록 규칙으로만 판정한다. 실제 딜명·수치·회사명·개인 식별정보는 저장소에 남기지 않는다.

## 1. 방향 (불변)

모델터는 한국 상업용 부동산(CRE) 실무자가 **IM을 받은 순간부터 IC 보고까지**를
브라우저 하나로 끝내게 하는 도구다. 핵심 약속 세 가지:

1. **화면 = 다운로드 엑셀** (파리티) — 화면 수치와 엑셀 수식이 같은 계산식
2. **딜 데이터는 서버로 가지 않는다** — 계산·저장·공유 전부 브라우저 안에서
3. **설치·가입·빌드 없음** — 링크 하나로 열리고, 저장소 사본이 곧 배포 사본

## 2. 아키텍처 정책 v2 (2026-07-09 개정)

### 결정

- **"650KB 또는 400함수 초과 시 분리 검토" 크기 임계를 폐지한다.**
- 대신 **CI가 강제하는 사용자 체감 성능 예산**으로 대체한다 (아래 표).
- 단일 파일 구조는 유지한다. 예산이 깨질 때만 아래 에스컬레이션 사다리 순서로 대응한다.

### 왜 폐지하나 — 실측 근거

찬반 대립 검증(각 측이 저장소를 직접 실측)으로 확인된 사실:

| 쟁점 | 실측 결과 |
|---|---|
| 원본 크기(667KB)와 사용자 체감 | 무관 — 실제 전송량은 gzip 213KB·brotli 168KB. 파일의 절반은 코드가 아닌 데이터(엑셀 템플릿 JSON·PPT 양식 base64 등 220KB+) |
| 로딩 시간 | 데스크톱 첫 결과 0.7초, 중급 모바일 근사 2.8초, 저가 모바일 근사 4.1초 — 크기가 아니라 **부트 지점(첫 렌더 코드)까지의 바이트**가 결정 |
| 출력 레이어(310KB) 분리 효과 | **첫 결과 시간 개선 ≈ 0ms** — 출력 레이어는 파일에서 부트 지점 *뒤*에 있어, HTML 스트리밍 파싱 특성상 첫 렌더가 그 바이트 도착 전에 일어남 (블록 제거 실험으로 검증) |
| 실제로 발견된 심각한 로딩 문제 | 외부 폰트 CSS 렌더 블로킹(사내 프록시에서 13초 백지) — **파일 크기와 무관**, 크기 임계로는 영원히 못 잡는 유형. 비동기 로딩으로 수정 완료(13초+→0.44초) |
| 분리의 실비용 | 빌드 없는 정적 배포에서 파일 간 **버전 스큐**(구 HTML+신 JS 조합) 장애 계열이 새로 열림. 5.5주간 101회 배포 빈도에서 매 배포가 위험 창. 검증 체계(마커 180+건·파리티 하네스) 재작성 필요 |
| 단일 파일의 사용자 이익 | 원자적 배포(스큐 원천 차단) + **로드 후 전 기능 무네트워크 동작**(딜 미팅·불안정 와이파이에서 엑셀 생성 보장) + 공유 링크 디코더가 HTML과 항상 동행 |

결론: 크기 임계는 사용자 지표가 아니라 개발자 지표이며, 그 임계가 벌점 주는 방향(파일이 커지더라도
폰트 인라인 같은 사용자 이익 수정)과 사용자 이익이 충돌한다.

### "골대 이동" 방지 — 폐지가 방치가 아닌 이유

기존 임계는 채팅 산문이라 **집행력이 없었다**. 새 예산은 CI가 빌드를 실패시킨다:

| 예산 항목 | 기준 | 집행 지점 | 현재 |
|---|---|---|---|
| gzip 전송량 | **< 300KB** | `tools/modelter-ci-check.js` (하드 게이트) | 213KB |
| 렌더 블로킹 외부 CSS | **0건** | 〃 (하드 게이트) | 0건 |
| HTML 캐시 정책 | no-cache 재검증(구버전 고착 방지) | 〃 | 적용 |
| 입력 반응성 (dev 재계산) | **< 500ms** | `tools/qa/smoke.js` (하드 게이트) | ~130ms |
| 저가 모바일 근사 첫 결과 | ≤ 5s (경보성 — CPU 6x·Fast3G) | `tools/qa/perf-load.js` (수동 측정) | 4.1s |

### 에스컬레이션 사다리 — 예산 초과 시 이 순서로

1. **데이터 다이어트**: 티저 PPT 내장 양식(base64 46KB)을 IC 패키지처럼 XML 직접 생성으로 재작성,
   중복 문자열 데이터 축소. (전송량 -30KB+ 예상, 위험 최소)
2. **부트 지점 앞 최소화**: 첫 렌더 전에 실행되는 코드만 앞 블록에 — 새 출력·부가 기능은
   반드시 부트 지점 뒤에 추가한다(첫 결과 시간을 지키는 배치 규칙). 필요 시 블록 재배치로
   온보딩·위저드를 앞당김.
3. **최소 절개 분리** (최후 수단): 출력 레이어(엑셀 생성기·티저·IC·렌트롤 파서·BYOK) 1개 파일만 분리.
   반드시 함께 구현할 것 — ① `?v=<커밋해시>` 쿼리 캐시버스팅 ② 청크 no-cache ③ idle 프리페치 +
   클릭 시 재시도 ④ 기존 null 가드(`if(window.TEASER)` 등) 유지 ⑤ CI·파리티 하네스를 연결 소스
   기준으로 수정 후 4딜 파리티 전수 재검증. (모듈 경계는 이미 독립 IIFE + 전역 네임스페이스로
   존재하므로 절개 자체는 저비용 — 스큐 설계가 본 비용)

재검토 트리거: gzip 300KB CI 게이트가 깨지거나, 계기판(`tools/modelter-ae.js`)에서 모바일 비중이
높고 이탈이 확인될 때. 그 전에 선제 분리하지 않는다.

### 2026-08-15 북극성 획득 실험 — IM 첫 검토 체크리스트

**관찰:** 라이브 제품은 이미 “딜 받았으면, 모델터부터” 메시지와 첫 입력·결과·팀 전달 동선을 갖췄다. 반면 최신 고정 창 표본은 아직 작고, 30일 판독의 병목은 신규 기능 부족이 아니라 검색 유입이다. 이 상태에서 핵심 화면을 다시 바꾸면 원인을 분리할 수 없다.

**개입:** 새 계산 기능 대신 `/im-checklist` 정적 착지 한 면을 추가한다. “상업용 부동산 IM 검토 체크리스트”를 찾는 실무자가 자료의 기준·단위 → 딜별 최소 가정 → 첫 결과 → 팀 전달 문장까지 한 장에서 확인하고 기존 4개 계산기로 바로 들어가게 한다. 페이지 CTA는 `src=imcheck`만 보내며 딜 수치·회사명·PII를 보내지 않는다.

**진입 정합:** 후속 코드 감사에서 기존 검색 착지의 첫 입력 강조가 `src=seo`에만 적용돼, 새 `imcheck`와 기존 `howto`는 계산기에 도착한 뒤 첫 입력 인계를 받지 못하는 것을 확인했다. 새 UI를 만들지 않고 같은 표시 전용 하이라이트·안내·데스크톱 포커스를 `seo`·`dscr`·`imcheck`·`howto` 4채널에 공통 적용한다. 리파이에서도 맞도록 “매입가부터”는 “첫 입력부터”로 일반화하며, 새 이벤트나 판정 기준은 추가하지 않는다.

**사전 판정:** 배포 후 최소 7일과 `imcheck` 세션 20건을 모두 채우기 전에는 성공·실패를 말하지 않는다. 그 뒤 `session → activate` 15% 이상이고 실제 산출물까지 이어지면 유지·확대, 15% 미만이면 새 기능을 만들지 않고 검색 의도·문구·내부 링크부터 고친다. 이 실험은 유입면 판정이며, `docs/NORTH_STAR_EVIDENCE.md`의 고정 14일 팀 전달·첫 숫자·질적 증거 기준을 바꾸거나 대신하지 않는다.

### 2026-08-15 DSCR 검색 의도 실험 — 노출을 첫 계산으로 연결

**관찰:** Search Console의 2026-07-21~08-13 고정 구간에서 `dscr 뜻`은 43회 노출·0클릭·평균 9.2위였고, 착지 URL은 `/t/dscr` 한 면으로 확인됐다. `부채상환계수`와 `dscr`도 각각 9회 노출·0클릭이었다. 이미 첫 페이지 부근에 노출되는 수요가 있으므로 새 계산 기능보다 검색 결과의 약속과 착지 후 판독 깊이를 먼저 고친다.

**개입:** 제목을 `DSCR 뜻과 계산식 — 1.2x는 무슨 의미일까?`로 구체화하고, 1.0x·1.2x·1.5x 판독표, NOI·금리·LTV·상환 방식의 영향, 약정별 NOI/NCF/CFADS 차이, 실무 FAQ를 한 면에 추가한다. CTA는 `src=dscr` 채널명만 전송해 계산기 진입 뒤 활성화·산출물까지 기존 `seo`와 분리한다. 전 생성 페이지의 푸터에는 `/im-checklist` 링크를 추가해 용어 탐색이 IM 첫 검토 워크플로로 이어지게 한다.

**사전 판정:** 배포 후 최소 14일과 DSCR 관련 쿼리의 배포 후 노출 100회를 모두 채우기 전에는 성패를 말하지 않는다. 그 뒤 관련 쿼리 CTR 5% 이상이고 `dscr` 세션에서 실제 `activate`가 확인되면 유지한다. CTR이 5% 미만이면 제목·설명을, 클릭은 있으나 활성화가 없으면 착지 CTA·예시 연결을 먼저 고친다. 검색 순위 변동과 표본이 작으므로 클릭 증가만으로 팀 반복 채택을 주장하지 않으며, 북극성의 고정 증거 창은 그대로 유지한다.

## 5. 획득·채널 월간 리뷰 루틴 (E5 — 시간 배분의 데이터화)

1인 운영이므로 "어디에 시간을 쓸지"를 감이 아니라 데이터로 정한다. 월 1회, 아래 한 줄을 돌린다:

```bash
CF_ACCOUNT_ID=xxxx CF_API_TOKEN=yyyy node tools/modelter-ae.js --days 30 --attribution --snapshot
git add data/ae-snapshots && git commit -m "계기판 월간 스냅샷"   # AE 90일 보존 극복 → 영구 추세
node tools/modelter-report.js   # data/dashboard.html 갱신(로컬 확인용, 커밋 안 함)
```

**무엇을 보고 무엇을 정하나 (채널 → 산출물 전환 기준)**

| 신호 | 본다 | 결정 |
|---|---|---|
| `--attribution` 채널(src)별 퍼널 | 어느 링크(`src=xlsx`·`notes`·`hero` 등)가 방문→산출물까지 가나 | 전환 높은 채널에 시간 집중, 낮은 채널(E2·E3·E8 산출물)은 문구·CTA 교체 또는 중단 |
| 유입 호스트별 퍼널 | 검색·직접·특정 사이트 중 실사용 채널 | E3(검색 착지) 지속·확대 여부 |
| `deal_want` 딜 유형 분포 | 준비 중 타일에서 어떤 유형 수요가 실재하나 | 특정 유형 수요 누적 시에만 그 딜 커버리지 착수(데이터 전 선착수 금지) |
| 모바일 비중·이탈 | 기기별 세션·전환 | 모바일 이탈 확인 시에만 성능 투자(아키텍처 정책 재검토 트리거) |

**src 태그 규약:** 산출물 회수 링크·검색 착지·노트 CTA가 `#…&src=<채널>` 를 붙인다(영문·숫자 8자, 화이트리스트). `xlsx`·`ppt`·`png`·`qr`·`notes`·`hero`·`team` 등. **채널명뿐 — 수치·PII 절대 금지**(worker.js 정화 + trust.html 표기 + CI 게이트로 3중 강제).

**운영자 QA 모드:** 배포 확인·시연 전 본인 기기에서 `modelter.com/#qa=on` 한 번 열면 그 기기의 사용이 통계에서 제외된다(localStorage, `#qa=off`로 해제 — 켜고 끌 때 토스트로 확인). 리뷰 수치를 보기 전 "내 사용이 섞였나?"를 의심할 필요가 없어진다.
