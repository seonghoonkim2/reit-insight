발견한 코드 결함은 성장 가설과 구분한다. 자동 복원에서 렌트롤 및 저장한 딜의 연결이 빠지는 문제, 검색 페이지의 예시 조건과 계산기 예시가 다른 문제, 전체 이벤트의 기기별 건수를 방문 수로 나눈 보고서 오류는 재현·수정 대상이다. 이 결함들이 방문 감소를 일으켰다는 인과관계는 아직 확인되지 않았다.

## 작업별 세부 명세

### 저장한 검토를 그대로 다시 열기

브라우저를 닫거나 페이지를 새로고침해도 직전에 검토하던 숫자와 계산 방식이 유지되어야 한다. 이름 있는 딜이라면 어느 버전을 보고 있었는지도 남긴다. 아직 저장하지 않은 수정이 있었다면 그 사실을 유지하고, 저장된 버전을 몰래 덮어쓰지 않는다.

공유 링크와 검색 예시를 잠깐 보는 행동은 기존 작업을 바꾼다는 뜻이 아니다. 명시적으로 자기 작업으로 전환하거나 수정·저장하는 시점을 구분한다. 다른 딜 예시나 전체 비우기는 기존 딜의 저장 연결을 해제한다. 삭제된 버전, 오래된 저장 형식, 잘못된 JSON, 저장 공간 부족에서도 거짓 저장 완료를 표시하지 않는다.

검사는 일반 매입·활성 렌트롤·개발·리파이, 저장 전후, 미저장 변경, 공유 링크, 모바일, 저장 실패를 포함한다. 엔진과 Excel 수식은 이 작업에서 변경하지 않는다. 입력 복원이 계산 경로를 바꾸는 만큼 결과 일치와 개인정보 회귀 검사는 수행한다.

### 검색에서 계산까지 같은 내용을 보여주기

현재 있는 계산기 소개와 용어 페이지를 먼저 손본다. 물류 매입 페이지는 실제로 받는 통합 임대료와 지원되는 계약 모델을 설명한다. 층별 임대료나 마스터리스 별도 기능이 있는 것처럼 쓰지 않는다. 공동주택 개발과 물류센터 개발을 구분한다.

예시 입력값은 앱의 같은 자료를 참조해 생성한다. 결과 숫자를 설명 페이지에 별도로 고정해 두지 않는다. 수익률은 현재 계산기로 열어 확인하게 하고, 글에는 결과를 해석할 때 확인할 조건을 적는다. 법정 세율·세무 판단·시장 참고치는 출처와 적용 범위를 확인한 경우에만 쓴다.

다음 내용 개선은 실제 검색 질문과 연결한다. 후보는 물류센터 매입 시 공실과 계약 만기의 영향, 리파이 시 대출 한도와 만기 상환 부담, DSCR에 들어가는 원리금의 범위, IM 수치가 부족할 때 먼저 확인할 항목이다. 첫 단계에서는 기존 페이지 중 1~2개를 선택한다. 각각 입력 예시, 빠지기 쉬운 가정, 관련 계산기 진입 하나로 구성한다. 사이트 하단에 링크 목록을 더 쌓지 않는다.

### 첫 입력을 쉽게 만들기

소개문을 더 읽게 하기보다 이미 있는 핵심 입력을 찾기 쉽게 한다. 오피스·물류는 매입가 또는 직접 NOI, 개발은 토지비, 리파이는 NOI 등 실제 계산의 시작 필드를 우선한다. 자산명 입력을 선행 조건으로 두지 않는다. 단위와 예시 상태는 숨기지 않는다.

모바일에서는 자동 포커스로 키보드를 올리지 않는다. 사용자에게 보이는 입력 시작 버튼을 눌렀을 때의 위치, 숫자 입력, 결과 이동, 다운로드를 실제 브라우저에서 확인한다. 네이버 모바일 30회 중 입력 0회는 조사 우선순위의 근거이며, 특정 문구 변경의 효과를 입증한 데이터가 아니다.

### 다시 사용할 이유 만들기

재방문의 이유는 바뀐 매입가, 새로 받은 임대조건, 대출조건 회신, 동료의 질문이다. 새 알림 서비스를 만들기보다 기존 딜·버전·비교 기능을 이 순서로 연결한다. 최근 검토는 저장된 딜이 있는 사람에게만 보여주고, 브라우저에만 저장된다는 사실과 백업 방법을 가까이 둔다.

먼저 현재 버전의 표시와 번호 발급을 고친다. 기존 선택지는 선택한 버전 대신 버전 개수를 표시하며, 중간 버전 삭제 뒤에는 같은 번호가 다시 붙을 수 있다. 과거 번호는 보존하고 딜별 최대 발급 번호를 유지해 새 번호를 부여한다. 다음으로 실제 입력을 마친 미저장 결과에만 “이 조건 저장” 행동을 연결한다. 기존 25초 후 저장·공유 토스트는 바로 실행할 버튼이 없어, 토스트를 더 늘리지 않고 결과 근처의 한 행동으로 정리하는 안을 검토한다. 새 최근 작업 화면을 만들기보다 기존 보관함에서 현재 조건과 이전 조건을 확인하기 쉽게 한다.

후속 콘텐츠는 `/im-checklist`→`/howto`→`/t/noi` 순서로 진행한다. 첫 페이지는 앱에 없는 층별 임대료 입력과 리파이 손익분기 결과 설명을 실제 지원 범위로 고친다. 사용 안내는 매입가 수정→새 버전 저장→다시 열기→이전 조건 비교→읽기 전용 공유 한 흐름을 설명하고, 예시를 약속하는 링크가 실제 예시를 열게 한다. NOI 용어 페이지에는 임대료 자료가 있는 경우와 연 NOI만 있는 경우의 입력 방법·단위만 추가한다. 기존 정의와 경로를 유지하고, 각 설명을 실제 버튼·입력·다운로드로 확인한다. `/t/noi`의 계산기 유입은 다른 용어 페이지와 `seo`로 합산되므로 현재 로그만으로 해당 페이지의 효과를 분리하지 않는다.

Excel 수정값을 웹으로 가져오는 기능은 이후 후보로 둔다. 첫 범위는 표준 매입의 매입가·임대료 또는 직접 NOI·Exit Cap·차입조건·보유기간이다. 가져오기 전에 변경표를 보여준다. 수식 수정, 행 이동, 미지원 가정, 오래된 파일을 원본 상태로 오인하지 않게 해야 한다. 가져오기→계산→재다운로드의 지원 항목과 결과 일치 검사를 통과하기 전에는 제공하지 않는다.

### 전문성이 드러나는 결과와 소개

제작자의 전문성은 과장된 문구보다 정확한 가정·단위·수식·범위에서 드러나게 한다. 실제 사례처럼 보이는 가상 수치를 만들지 않는다. 샘플은 샘플로 표시하고, 계산으로 확인할 수 있는 내용과 추가로 확인할 자료를 나눈다.

공유 요약은 딜 유형, 주요 가정, 핵심 결과, 미확인 조건 순서로 읽히게 한다. 제작자 소개와 연락 경로는 기존 위치를 활용한다. 연락 버튼을 반복 노출하거나 가입을 요구하지 않는다. 외부 소개글이 필요하면 검증한 사용 예시로 초안을 만들고, 사용자 승인 없이 LinkedIn·블로그·이메일에 게시하거나 발송하지 않는다.

## 효과 판정

아래 수치는 달성 약속이 아닌 초기 목표다. 실제 운영 반영 UTC 시각을 경계로 배포 전 28일과 배포 후 28일을 같은 정의로 비교하고, 요일·유입 구성과 계측 변경을 함께 확인한다. 시작 시각은 포함하고 끝 시각은 제외해 두 창이 겹치지 않게 한다. 모든 지표는 이 절대기간의 SQL로 조회한다. 배포가 UTC 자정이 아니면 일별 집계로 경계일을 정확히 나눌 수 없으므로 이를 대입하지 않는다. 지금의 30일 합계나 겹치는 스냅샷도 28일 기준선을 대신하지 않는다. 실사용 산출물은 기존 Analytics Engine의 `blob11`로 같은 창을 분해한다. 조회할 수 없으면 해당 항목은 판정을 보류한다. 기간 경계를 넘는 세션은 단계별 이벤트가 서로 다른 창에 기록될 수 있어, 집계 비율이 동일 사용자 집단의 전환 확률을 증명하지는 않는다.

|---|---|---|
| 발견 | 봇 제외 방문, 구글·네이버별 방문과 입력 | 28일 방문 +20%를 방향 목표로 둔다. 동시에 입력률이 떨어지면 유입의 질을 조사한다. |

임계값에 못 미쳤다는 이유만으로 작동하는 기능을 즉시 삭제하지 않는다. 기술적 오류를 먼저 구분하고, 유입 구성과 표본을 확인한 뒤 한 변수씩 조정한다. 사용자 ID나 딜 숫자를 새로 수집해서 보완하지 않는다.

## 계속 작업하는 방식

이 채팅의 시간당 이어가기 실행은 먼저 `GROWTH-WORKLOG.md`와 Git 상태를 읽는다. 진행 중인 검사나 다른 실행이 있으면 같은 파일을 중복 수정하지 않는다. 완료된 작업을 다시 검사하기만 하는 반복은 피하고, 해결되지 않은 우선 항목을 선택한다.

매 실행에서 근거 확인→작은 수정→관련 회귀 검사→독립 검토→결과와 다음 순서 기록까지 수행한다. 승인 전 변경은 검토 브랜치에 모으되, PR 기준점과 의존 관계를 명시한다. 코드 변경을 끝내면 문서·미리보기·배포 후 확인 절차처럼 독립적으로 진행할 수 있는 다음 작업으로 넘어간다. 외부 계정이나 실제 사용 자료가 없어 확인하지 못하는 일은 그 한계를 기록하고 다른 항목을 진행한다.

사용자가 멈추라고 하면 반복 실행과 진행 작업을 중단한다. 새 요청이 방향을 바꾸면 계획을 갱신한다. 변화 없는 상태 보고는 반복하지 않고, 의미 있는 결과나 문제를 발견했을 때 알린다.

## 검증과 배포

저장소의 빌드 스탬프→파리티 공표→정적 페이지 생성→CI→불변식→브라우저 검사 순서를 지킨다. 계산이나 Excel 생성기를 바꿀 때는 11개 파리티와 관련 편집 검사를 추가한다. 저장·공유 변경은 데이터 유실, 임차인명 마스킹, 외부 전송 부재를 별도로 확인한다. 성능 예산과 기존 화면·엑셀의 색감을 유지한다.

배포 승인이 오기 전에는 master에 병합하지 않는다. 배포할 때는 승인된 커밋의 필수 CI를 다시 확인하고, 이후 운영 빌드·검색 경로·대표 사용자 흐름·다운로드 파일을 검사한다. 운영 반영 전의 기능 검사 통과를 방문 증가의 증거로 보고하지 않는다.
