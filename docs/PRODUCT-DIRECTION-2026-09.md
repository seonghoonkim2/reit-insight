# 모델터 목적과 90일 실행계획

2026-09-10 · 사용자 답변을 반영한 제안 · 일정과 수치는 목표 초안

## 1. 프로젝트 목적

**본인과 동료가 상업용 부동산의 최초 딜 검토를 시작하고, 조건이 바뀌면 다시 이어서 검토하는 실무 도구를 만든다. 그 사용 경험을 통해 제작자의 전문성·인지도와 업무 기회·인맥이 쌓이게 한다.**

수익화는 목표에 넣지 않는다. 우선 사용자는 본인과 동료다. 방문자 확대는 이들이 실제 딜에 반복 사용하는 흐름을 확인한 뒤 강화한다.

제품의 약속: **딜의 입지·거래 근거와 핵심 가정을 한곳에 정리해, 추가 검토할 쟁점과 첫 계산을 남긴다. 다음 방문에는 그 검토를 이어간다.**

서비스의 성공과 제작자의 목적을 연결한다.

- 실무 가치: 첫 검토 준비 시간과 재검토 때 다시 찾는 수고를 줄인다.
- 반복 사용: 딜의 조건 변경·자료 회신·팀 질문에 대응할 때 다시 연다.
- 전문성: 계산식·근거·검토 방법이 명확한 결과물을 동료가 신뢰한다.
- 확산: 유용한 검토 방법과 샘플이 추천·검색·업무 대화로 이어진다. 문의를 위한 입력 강제나 가입 장벽은 만들지 않는다.

## 2. 핵심 사용자 흐름

딜/주소 등록 → 네이버지도·디스코·밸류맵에서 근거 확인 → 핵심 숫자 입력 → 1차 검토 요약 → 검토 기록 저장 → 조건 변경 시 이어서 검토

주소를 모르면 숫자부터 시작할 수 있다. 오피스 매입을 첫 구현 사례로 삼되 물류·개발·리파이 접근은 유지한다. 새 흐름이 다른 딜에도 맞는지 별도로 검토한다.

### 화면을 세 곳으로 정리

| 화면 | 바로 보여줄 것 | 필요할 때 열 것 |
|---|---|---|
| 시작 | 새 딜 검토, 최근 검토 이어가기 | 사용 예시, 제작자·방법론 |
| 딜 검토 | 대상/주소, 근거 링크, 핵심 가정, 다음 확인사항 | 세부 운영비, 자본구조, 세무, 렌트롤, AI 도구 |
| 결과 | 핵심 지표, 가정 출처, 하방, 미확인 쟁점, 엑셀·검토 저장 | 민감도 전표, 연도별 CF, 다른 출력 형식 |

첫 화면의 반복 소개와 동등한 기능 버튼을 줄인다. AI 시트 설계·세부 산출물·준비 중 딜을 주 작업과 같은 시각적 우선순위에 두지 않는다. 딜 유형별 입력 형식은 기존 엔진에 맞춰 열고, 기본값을 쓴 항목은 결과에도 표시한다.

‘3개 숫자만으로 검토 완료’라는 약속은 하지 않는다. 매입가·NOI/임대료·면적으로 시작할 수 있어도 차입·보유·매각 가정이 추가로 필요하다. 입력 채움, 가정 확인, 투자 판단을 구분한다.

## 3. 외부 사이트 연결

사용자가 실제로 사용하는 **네이버지도·디스코·밸류맵**을 1순위로 둔다. 공시·금리 화면은 이번 우선 범위에서 제외한다.

| 서비스 | 모델터에서 이어갈 작업 | 1차 구현안 |
|---|---|---|
| 네이버지도 | 입지·접근성 확인 | 사용자가 선택해서 지도 열기, 확인한 페이지 링크와 한 줄 메모를 딜에 저장 |
| 디스코 | 대상 물건·거래사례 확인 | 원문 링크 저장, 필요한 비교사례를 사용자가 요약 입력 |
| 밸류맵 | 거래사례 교차 확인 | 원문 링크·확인일·면적 기준·비교 메모 저장 |

**단계 A — 자료 연결:** 외부 원문 열기와 링크/메모 보관. 검색·개별 물건으로 직접 여는 주소 형식은 실제 동작 확인 후 사용한다. 지원이 확인되지 않으면 공식 사이트를 열고 검색어를 사용자가 복사한다. 연결 버튼을 자동 데이터 수집이라고 부르지 않는다.

**단계 B — 근거를 계산에 연결:** 각 가정에 ‘IM/사용자/외부 참고/기본값’과 기준일을 표시한다. 거래사례는 거래시점·자산유형·연면적/대지면적 기준을 나눠 사용자가 비교하도록 한다. 사례 가격을 해당 딜의 적정가격이나 임대료로 자동 확정하지 않는다.

**단계 C — 자동 조회는 조건부:** 직접 연결의 이용과 수작업 부담이 확인된 항목만 검토한다. 네이버 지도 API는 공식 등록 절차가 있지만, 이는 디스코·밸류맵의 거래정보를 가져올 권한이나 기능을 의미하지 않는다. 이번 확인 범위에서 디스코·밸류맵의 자동 수집에 필요한 공개 API·이용범위는 확정하지 않았다. 제공 범위·허용 조건·비용·유지보수를 확인한 뒤 구체화한다.

외부 열기는 사용자 동작으로만 수행한다. 주소 검색을 전달하는 경우 목적지와 전달되는 검색어를 버튼에 알린다. 딜 수치·원본 IM·임차인명은 외부 조회 요청에 포함하지 않는다. 외부 URL과 메모는 로컬 딜 기록에만 저장하고 이벤트에는 서비스 구분 같은 제한된 범주만 사용한다. 공통 백엔드로 전체 딜을 보내는 설계를 피한다.

확인한 공식 자료:

- [네이버 Maps 등록 안내](https://www.ncloud.com/support/faq/prod/1044?categoryCode2=APP&categoryCode3=SV_0062): 서비스 신청·결제수단·사용 URL 등록 안내. 실제 요금·기능은 구현 시 다시 확인한다.
- [디스코](https://disco.re/): 원문 검색·지도·물건 확인 경로.
- [밸류맵](https://www.valueupmap.com/): 공식 서비스 진입점. 자동 연동 명세는 이번 확인에서 확보하지 않았다.

## 4. 재방문 이유

사용자의 업무 사건에 붙인다.

| 다시 여는 순간 | 보여줄 것 | 기존 기능의 활용 |
|---|---|---|
| 매도자가 가격을 바꿨다 | 마지막 가정과 이번 변경, 결과 차이 | 딜 버전·가정 비교 재사용 |
| 임대료·대출 조건을 회신받았다 | 미확인 사항과 근거, 바꿀 입력칸 | 출처 메모·기존 입력폼 연결 |
| 팀에서 다시 물어봤다 | 검토 요약·근거 링크·엑셀 | 기존 산출물과 공유 경로 단순화 |
| 다른 딜을 받았다 | 기존 검토를 복제해 새 딜 시작 | 워크스페이스·프리셋 재사용 |

홈의 ‘최근 검토’가 가장 먼저 구현할 재방문 장치다. 수년치 거래관리나 공동 편집 시스템으로 확대하지 않는다. 현재 로컬 저장 구조는 동일 브라우저에서 이어쓰기를 지원하는 출발점이며, 자동 기기 동기화나 팀 공유 저장소로 표현하지 않는다. 저장 위치 안내와 파일 백업·복원 경로를 함께 보이게 한다.

변경된 가격이 외부 사이트에서 자동 탐지된 것처럼 표시하지 않는다. 초기에는 사용자가 직접 반영한 변경을 비교한다. 자동 알림·메일·주간 뉴스 기능은 이번 계획에 넣지 않는다.

## 5. 90일 실행 순서

달력 일정은 작업량 추정이다. 각 단계의 사용자 검토와 배포 승인에 따라 조정한다.

| 시기 | 목적 | 결과물 | 다음 단계로 넘어갈 기준 |
|---|---|---|---|
| 1~2주 | 화면 구조 합의 | 시작·딜 검토·결과의 클릭 가능한 설계안, 변경 전후 표시 | 본인이 시작/이어가기 위치를 설명 없이 찾고 주요 정보 순서를 수용 |
| 3~4주 | 첫 검토 동선 단순화 | 기존 엔진에 새 화면 연결, 세부기능 접기, 엑셀·저장 행동 정리 | 본인+동료 최대 5명 관찰에서 핵심 흐름 완수, 계산/엑셀 검증 통과 |
| 5~6주 | 외부 근거와 연결 | 네이버지도·디스코·밸류맵 링크, 근거 메모·가정 출처 | 파일럿에서 실제 검토 근거를 남기고 다음 방문에 다시 찾는지 확인 |
| 7~8주 | 재검토 마찰 줄이기 | 최근 검토 홈, 미확인 사항, 이전/현재 조건 비교 | 5명 중 3명이 별도 날짜의 실제 딜 검토에 2회 이상 사용한다는 목표를 평가 |
| 9~12주 | 사용 경험을 외부로 확산 | 검증된 검토 예시·방법론 정리, 검색 착지 개선, 소개·연락 경로 정리 | 반복 사용과 방문 추세를 함께 보고 다음 투자 결정 |

외부 자료 연결의 간단한 시안은 1~2주에 함께 보여준다. 실제 조회·저장은 단계별 검증 후 연결한다. 동료 접촉이나 콘텐츠 게시는 사용자가 직접 하거나 명시적으로 요청한 경우에만 진행한다.

## 6. 성공 지표

첫 2주에 정의를 정리하고 기준선을 고정한다. 아래는 약속된 성과가 아닌 초기 판정 기준 제안이다.

- **핵심: 확인된 반복 실사용.** 본인 포함 최대 5명 파일럿 중 3명이 서로 다른 날짜에 실제 딜 검토로 2회 이상 사용. ‘같은 딜 재검토’와 ‘다른 딜 검토’를 구분해 묻는다. 딜 내용·파일·회사명은 수집하지 않는다. 참가자 확인은 동의받은 별도 비공개 기록으로 수행한다.
- **획득: 동일 정의의 28일 방문 추세.** 봇 제외·페이지 실행 단위 등 집계 정의를 고정한 뒤 직전 28일 대비 +30%를 90일의 도전 목표로 제안한다. 계측 정의가 바뀌면 과거 742 등을 바로 분모로 섞지 않는다. 고유한 사람 수와 페이지 시작 수를 구분한다.
- **행동 진단:** 입력 시작, 근거 링크 보관, 저장 딜 열기, 파일 생성 성공을 구분한다. 기존 클릭 수를 생성 성공으로 부르지 않는다.
- **실무 효과:** 같은 검토 과업을 평소 방식과 모델터로 수행할 때 시간과 빠진 항목을 비교한다. 20% 시간 절감은 파일럿 가설이며 실제 자료의 복잡도를 맞춰 관찰한다.
- **제작자 목적:** 추천을 통해 들어온 업무 대화·새 관계·문의의 발생을 본인이 월 1회 확인한다. 연락 버튼 클릭만으로 인맥 형성이나 업무 기회라고 판단하지 않는다.

계정·사용자 추적 ID 없이 이벤트만으로 사람 단위 리텐션을 정확히 계산할 수는 없다. 익명 로그는 경로 진단에 쓰고, 반복 실사용 여부는 초기 파일럿으로 보완한다. 방문만 늘고 반복 사용이 없으면 외부 홍보 확대보다 재사용 장애를 먼저 해결한다.

## 7. 실행·승인 원칙과 이번 작업의 위치

앞선 1차 검토본의 LTV·예시 상태·AI 시트 구분·모바일 이동은 **정확성 정비**로 둔다. 사용자가 원하는 주요 화면 개편은 이 목적을 기준으로 다시 설계한다.

이번 결과물은 전체 목적/계획과 시작·근거 확인 화면의 방향 시안이다. 시안은 가상 예시이며 실제 계산·저장·외부 연동이 연결된 운영 기능이 아니다. 홈의 ‘새 검토/이어가기’ 배치와 외부 근거를 함께 보관하는 흐름을 판단하기 위한 것이다.

구현 단계에서는 변경 전후 화면을 동일 시나리오로 비교하고, 바뀐 영역을 표시한다. 사용자가 검토할 수 있는 로컬 수정본 → 피드백 반영 → 기술 검증 → **사용자의 명시적 배포 승인** → PR 검증·병합·배포 확인 순서를 따른다. 승인 전 master 병합·운영 배포 금지.

모든 작업은 단일 앱 파일·딜 데이터 비전송·화면/엑셀 일치·기존 성능 예산을 유지한다. 저장·외부연결 변경 시 이전 딜 파일 복원, 읽기 전용 공유, 조회 실패, 모바일 사용을 함께 검사한다.
