## 다음 작업 순서

1. **현재 버전 표시·번호 발급 오류**: 선택지가 실제 선택한 버전 대신 버전 개수를 표시한다. `versions.length+1`은 중간 버전 삭제 후 같은 번호를 다시 만들 수 있다. 실제 `v.label`을 표시하고, 딜별 최대 발급 번호를 유지해 삭제 뒤에도 번호를 재사용하지 않는다. 기존 번호는 보존하고 저장 실패 때 번호도 되돌린다. 이전 버전 열기→중간·마지막 버전 삭제→새 저장→파일 메타 확인을 검사한다.
2. **IM 체크리스트 설명 정정**: `/im-checklist`의 층별 임대료 설명을 가중평균/렌트롤로 수정하고, 리파이 만기는 참고 항목으로 구분하며 없는 손익분기 결과 약속을 지운다. 앱의 실제 입력 이름·단위를 대응하고 4개 CTA를 확인한다. `imcheck` 방문 15회·입력 1회는 우선순위 근거이며 원인 증명은 아니다.
3. **결과에서 저장으로 이어가기**: 미저장 실제 입력 결과에만 기존 저장 기능을 실행하는 한 행동을 둔다. 저장·공유를 함께 권하는 토스트를 더 늘리지 않는다. 저장된 딜이 있는 경우 기존 보관함의 현재 버전·수정 상태·백업 접근을 정리한다. `ws_save` 성공 행동을 보며 `slot_save`를 성공률로 해석하지 않는다.
4. **사용 안내와 NOI 설명**: `/howto`를 수정→버전 저장→재방문→이전 조건 비교→읽기 전용 공유 한 흐름으로 정리한다. 딜별 엑셀 편집 범위와 실제 예시 CTA를 맞춘다. 그다음 `/t/noi`에 연 NOI만 있을 때의 입력 방법과 단위를 추가한다. `/t/noi`는 기존 `seo` 합산 로그에서 개별 효과를 분리할 수 없음을 유지한다.
5. **운영 효과 관찰 준비**: 승인된 배포 시각을 기준으로 앞뒤 완결 28일 창을 고정한다. 활성 세션 산출물의 28일 값은 기존 AE `blob11` 별도 조회가 필요하며 없으면 보류한다. 사람 단위 재방문과 실제 업무 기회를 이벤트 수로 대신하지 않는다.

필요 없는 큰 기능, 검색 페이지 증산, 새 가입 절차, 실제 딜 정보 수집은 추가하지 않는다. 승인 대기 중에도 독립적인 수정·미리보기·배포 후 확인 절차를 이어가되 master 병합과 외부 게시를 하지 않는다.
