## 다음 작업 순서

1. **결과에서 저장으로 이어가기**: 미저장 실제 입력 결과에만 기존 저장 기능을 실행하는 한 행동을 둔다. 저장·공유를 함께 권하는 토스트를 더 늘리지 않는다. 저장된 딜이 있는 경우 기존 보관함의 현재 버전·수정 상태·백업 접근을 정리한다. `ws_save` 성공 행동을 보며 `slot_save`를 성공률로 해석하지 않는다. 현재 파일의 gzip 여유가 작으므로 실제 추가 크기를 먼저 확인하고 기존 성능 예산을 유지한다.
2. **사용 안내와 NOI 설명**: `/howto`를 수정→버전 저장→재방문→이전 조건 비교→읽기 전용 공유 한 흐름으로 정리한다. 딜별 엑셀 편집 범위와 실제 예시 CTA를 맞춘다. 그다음 `/t/noi`에 연 NOI만 있을 때의 입력 방법과 단위를 추가한다. `/t/noi`는 기존 `seo` 합산 로그에서 개별 효과를 분리할 수 없음을 유지한다.
3. **운영 효과 관찰**: 실제 운영 반영 UTC 시각을 기준으로 앞뒤 정확한 28일 창을 고정한다. 모든 지표는 절대기간 SQL로 조회하고 활성 세션 산출물은 기존 AE `blob11`로 분해한다. 조회할 수 없으면 보류한다. 사람 단위 재방문과 실제 업무 기회를 이벤트 수로 대신하지 않는다.

필요 없는 큰 기능, 검색 페이지 증산, 새 가입 절차, 실제 딜 정보 수집은 추가하지 않는다. 승인 대기 중에도 독립적인 수정·미리보기·배포 후 확인 절차를 이어가되 master 병합과 외부 게시를 하지 않는다.
