# 팀 첫 검토 파일럿 — 실제 딜 3인 운영안

목적은 “좋다”는 평가를 받는 것이 아니라, 실제 CRE 딜 검토가 시작될 때 사람들이 어떤 도구를 열고 어떤 숫자를 먼저 보는지 확인하는 것이다. 이 문서는 실행 준비본이며 **현재 상태는 발송 0명 · 팀 채널 유입 0건 · 인터뷰 0건 · 질적 증거 0건**이다(2026-08-16 19:00 KST 스냅샷). 대상자 선택과 발송은 운영자가 직접 승인·실행한다.

## 증거 오염을 막는 원칙

- 기준선과 후속 질문이 끝나기 전에는 북극성 문장이나 기대 답을 보여 주지 않는다.
- 초대로 발생한 첫 사용은 자연 회상 증거로 세지 않는다. 그 뒤 다른 실제 딜에서 스스로 다시 열었을 때만 반복 사용 후보로 본다.
- 데모용 가상 과제가 아니라 실제 IM·티저·미팅 전 검토 한 건을 관찰 단위로 삼는다.
- 기능 요청이나 만족도는 별도 메모일 뿐, 채택 증거를 대신하지 않는다.
- 저장소에는 역할과 상황만 일반화해 남긴다. 이름·회사·실제 자산명·딜 수치·임차인명·연락처·직접 인용은 기록하지 않는다.

## 대상자 3명

서로 다른 실무 맥락을 우선한다. 같은 회사 여부보다 시작 순간이 실제로 다른지가 중요하다.

1. 매입·투자 검토 담당 1명 — IM·티저 수신 뒤 1차 수익성
2. 대주·재무 담당 1명 — 신규 대출 또는 차환안 비교
3. 자산관리·운용 담당 1명 — 보유자산 재검토 또는 팀 보고

한 팀에서 자연스러운 반복 언어를 확인하려면 위 3명 외에 같은 팀 동료 1명을 추가할 수 있다. 그래도 서로 다른 실무자 3명 기준은 낮추지 않는다.

아래 세 질문만 하고 답을 먼저 기록한다. 제품명이나 목표 문장은 말하지 않는다.

## 2단계 — 복사해 보내는 초대문

> 다음에 실제 IM이나 티저를 받고 1차로 숫자를 볼 일이 있으면, 정식 모델을 만들기 전에 아래 링크를 한 번 써 봐 주세요. 15분만 써도 됩니다. 투자 결론이나 정식 모델을 대신하는 테스트는 아닙니다. 입력한 값은 브라우저 안에서만 계산되고 서버로 보내지지 않습니다. 사용 후 10분 정도, 무엇부터 봤는지와 팀에 어떻게 공유했는지만 여쭙겠습니다. 실제 딜명이나 숫자를 제게 보낼 필요는 없습니다.

딜 유형에 맞는 **딜 값이 들어 있지 않은 기본 링크** 하나만 보낸다. 링크 자체에는 샘플 외 실제 딜 값이 담겨 있지 않다.

## 3단계 — 실제 딜 직후 후속 질문

사용 여부를 먼저 묻지 않고 아래 순서 그대로 묻는다.

1. 그 딜의 첫 검토를 시작할 때 무엇을 가장 먼저 열었나요?
2. 가장 먼저 확인한 숫자나 판단은 무엇이었고, 왜 그것부터 봤나요?

세 답변이 끝난 뒤에만 사용 여부, 막힌 지점, 다시 쓸 상황을 확인한다. “편했다”, “좋았다”, 기능 요청은 보조 정보다. 다른 실제 딜에서 자발적으로 다시 열었는지와 팀 동료가 먼저 사용 여부를 물었는지가 핵심이다.

## 4단계 — 익명 기록

개인 식별용 참가자 목록은 저장소 밖 운영자 메모에만 두고, 저장소에는 아래처럼 일반화한 한 줄만 추가한다.

|---|---|---|---|---|---|---|

- 위 네 링크는 딜 상태가 없는 진입 링크이며 `/e`에는 `team`이라는 채널명과 기존 익명 이벤트만 기록된다. 딜 수치·임차인명·개인정보는 보내지 않는다.
