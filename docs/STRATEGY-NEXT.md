## 1. 전략 방향 — "만들기"에서 "발견·허가·전파"로

### 배경
2026-07-09 기준 페르소나 발굴 백로그 32건 전량 완료. 딜 4종 엔진·파리티·렌트롤·IM 추출·IC 패키지·딜 보관함까지 **개인 실무자용 기능은 포화**다. 그런데 계기판(Cloudflare AE)은 수집만 되고 데이터가 없다 — 제품은 성숙했으나 **사용자가 사실상 0** 이라는 신호다.

코드로 실증된 공백 4가지:
1. **sitemap URL 3개** (`/`, `/guide.html`, `/howto.html`) — 검색 표면이 사실상 없다.
2. **보안팀 제출 문서 0장** — "무전송" 원칙이 코드(`worker.js` `/e` 화이트리스트)에만 있고 사람이 읽을 문서가 없다.
3. **하우스 기준은 `mt_house` localStorage 개인 한정** — 팀에 퍼뜨릴 수단(`#h=` 링크)이 없다.
4. **공유·산출물에 `src=` 채널 태그 0건** — 어느 경로로 사람이 들어오는지 측정 불가.

### 방향 명제
> **다음 6개월, 새 기능을 만들지 않는다. 이미 완성된 제품이 ① 검색·산출물로 발견되고, ② 보수적 금융회사에서 허가받고, ③ 팀 단위로 퍼지게 만든다 — 무전송·무가입·파리티라는 불변 원칙을 제약이 아니라 영업 무기로 뒤집어서.**

### 왜 지금 이 방향인가
- 기능 추가의 한계효용은 급감했고, 유통·신뢰 표면은 비어 있다 — **병목이 제품에서 유통·신뢰로 이동**했다.
- 사용자층(보수적 금융사 실무자)의 첫 관문은 기능이 아니라 **"보안팀이 허락하나, 시니어가 믿나"** 다.
- 유통 원자재는 이미 코드에 있다 — 공유 링크(LZW·임차인 마스킹)·QR·읽기 전용 착지·`refHost` 수집. **남은 것은 배선**이다.
- SEO·콘텐츠는 3~6개월 지연되는 복리 자산 — **지금 심어야 6개월 뒤 수확**한다.
- 1인 겸업 체제 — **저유지비 자산(정적 문서·링크·생성 스크립트)** 으로만 구성해야 지속된다.

### 3대 축
- **축1 · 허가(신뢰):** 신뢰 센터(`/trust`)+문서-코드 일치 CI, 재현성 스탬프·파리티 공표(`/verification`), 참고치 출처·기준일 → "무전송·화면=엑셀"을 주장에서 **검증 가능한 증거**로. → E1, E6, E7
- **축2 · 발견(획득):** 용어·계산기별 검색 착지 페이지 30+, 산출물(엑셀·PPT·PNG) 회수 루프, 분기 시장 노트 → 매일 사내에 도는 산출물과 검색이 **무료 획득 채널**로. → E2, E3, E8
- **축3 · 전파·측정:** `#h=` 팀 기준 배포 링크, 채널 어트리뷰션 계기판, 딜 수요 가짜 문 → 월 1회 데이터 리뷰로 **1인의 시간 배분을 결정**. → E4, E5

### 하지 않을 것 (안티골)
- 계정·로그인·서버 저장·클라우드 동기화 — 무전송이 최강의 보안 스토리다.
- 새 딜 유형·대형 엔진 개발 — **가짜 문(E5)·`im_extract` 데이터가 명확히 요구하기 전 금지.**
- 수년치 운용·예실 데이터를 localStorage에 얹는 기능 — 유실 가능한 저장소 위 장기 데이터는 기관이 승인하지 않는다.
- 익명 가정 벤치마크 — 옵트인 설계와 원칙 개정 절차 없이는 구현·공표 모두 금지.
- 격주 콘텐츠 공장·유료 광고·해외 확장 — 콘텐츠는 분기 1회 노트가 상한.
- 고정 버전 전체 아카이브·폐쇄망 패키지 — "항상 최신본" 철학과 충돌. 빌드 스탬프까지만(E6) 하고 수요 증거 후 재검토.
- 앱 본체 다중 파일화 — 신규 페이지는 전부 **앱 외부 독립 정적 문서**(성능 예산 v2 유지).
- 불변 규칙 완화 — `/e` 수치·PII 미수집, 임차인 마스킹, What's new v3 고정, "투자 권유 아님", `__mtCalc` 미배포.

### E1 · 신뢰 센터(/trust) — 보안팀 제출 가능한 검증 문서

**배경·목표**
실무자 스토리: *"이 도구 팀에서 써도 되나요?"라고 팀장·정보보호팀이 물으면 내밀 공식 자료가 지금은 0장이다.* 딜 데이터 무전송·수집 필드·BYOK 흐름을 사용자가 **직접(네트워크 탭) + 문서로** 검증하게 만들어, 조직 도입의 첫 관문(정보보호 검토)을 통과시킨다.

**현재 코드 기준점 (실증)**
- 텔레메트리 수집 필드는 `worker.js` `/e` 핸들러의 `rec` 객체가 유일 진실: `ev`(이벤트명 32자), `deal`(딜유형 16자), `depth`, `rr`(렌트롤 사용 0/1), `feats`/`featN`(기능 플래그), `axis`, `dev`(mobile/desktop), `ref`=`refHost`(유입 호스트 40자), `cc`(국가). **수치·임차인명·PII 없음** — 이 목록을 문서와 1:1로 박제한다.
- BYOK 흐름: `index.html` MTIM 모듈이 `fetch('https://api.anthropic.com/v1/messages', ...)` 로 브라우저→Anthropic 직행, 모델터 서버 무경유. 키는 메모리+선택 시 `sessionStorage('mt_byok_k')`, `localStorage` 절대 미저장.
- CSP·보안 헤더: `dart-search/web/modelter/_headers` 의 `Content-Security-Policy`(connect-src에 `api.anthropic.com`·`api.web3forms.com`·`cloudflareinsights.com`만) + `X-Frame-Options: DENY` 등.

**구현 설계**
1. `dart-search/web/modelter/trust.html` 신규 (독립 정적, 앱 CSS 톤 재사용, 인쇄용 `@media print`). 국문 1페이저로 인쇄되게.
2. 섹션: ① 한 줄 원칙("딜 숫자는 이 브라우저를 떠나지 않습니다") ② `/e` 수집 필드 전체 표(필드명·예시·왜 수집·**절대 수집 안 하는 것**) ③ "직접 확인하기 — F12 네트워크 탭 절차" 3스텝 ④ BYOK 데이터 흐름도(브라우저→api.anthropic.com, 모델터 서버 미경유) ⑤ CSP/헤더 해설 ⑥ 만든 사람 실명·소속·연락 ⑦ 개정 이력.
3. `worker.js` `/e` 필드 ↔ trust.html 표를 **CI로 강제**: `tools/modelter-ci-check.js` 에 worker.js의 `rec` 키 집합을 파싱해 trust.html에 모두 표기됐는지, 표기 외 필드가 없는지 검사(불일치 시 실패).
4. footer·온보딩·BYOK 모달에 `/trust` 링크 추가. sitemap 등록.

**파리티·불변 영향:** 없음(정적 페이지·계산 무관). 오히려 불변 원칙을 문서화해 강화.

**검증 계획:** Playwright — trust.html 렌더 무예외·인쇄 스타일 존재·`/e` 필드 표 존재. CI 마커: `html.includes('네트워크 탭')` + worker.js-trust 필드 일치 게이트. 파리티 불필요.

**수용 기준:** ☐ 인쇄 1~2장에 담김 ☐ `/e` 실제 필드와 표 완전 일치(CI 게이트) ☐ 네트워크 탭 자가 확인 절차가 실제로 재현됨 ☐ BYOK 흐름이 서버 미경유임을 명시.

**규모·리스크:** M. 리스크: 필드 문서화가 향후 `/e` 변경 시 어긋남 → CI 게이트가 방지.

**하지 말 것:** SOC2/ISMS류 형식 인증 주장 금지(1인이 감당 못 함·허위 위험), 폐쇄망 반입 패키지(수요 증거 후), `/e` 필드 추가(문서 동시 개정 없이 금지).

### E2 · 산출물 회수 루프 — 엑셀·PPT·PNG가 수신자를 되돌린다

**배경·목표**
스토리: *분석가가 만든 모델을 받은 상사·대주·동료가, 그 파일에서 클릭/QR 한 번으로 라이브 모델에 착지해 "내 딜로 새로 만들기"까지 간다.* 사용자 1명의 일상 업무(메일·회의)가 곧 신규 획득 행위가 되게 한다. **현재 산출물의 `modelter.com` 표기는 전부 클릭 불가 문자열** — 회수 루프가 없다.

**현재 코드 기준점 (실증)**
- 공유 링크 생성: `sharePayload()`(임차인명 마스킹 `'임차인'+A/B/...`), `encodeState()`=`mtLZ.compress`, `shareLink(readonly)` → `#v=`(읽기전용)/`#e=`(편집). `src=` 태그 **없음**(확인됨).
- 엑셀: `XLSXGEN.buildXlsx`, 커버는 `00_Cover` 시트. PPT: `ICPPT.build`(마지막 슬라이드 리스크·점검). PNG: `summaryCardPNG()`(1200×630, 하단 `modelter.com` **텍스트만**). QR: `window.__mtQrPop()`(이미 `#e=` 편집 링크를 QR로).
- 읽기 전용 착지: `enterReadonly()` + `#v=` 파싱(`tryRestoreFromURL`), 모바일 결과 우선 스크롤 구현됨. **하단 "내 딜로 새로 만들기" CTA 없음.**

**구현 설계**
1. 공유 링크 생성에 `src=` 채널 태그 파라미터 추가(E5와 공유): `shareLink(readonly, src)` → `#v=...&src=xlsx|ppt|png|qr|share`. `tryRestoreFromURL` 에서 `src` 파싱해 `mtTrack('landing',{src})` 1회 발화.
2. 엑셀 `00_Cover` 시트에 하이퍼링크 셀 추가 — "modelter.com에서 이 모델 열기"(`#v=…&src=xlsx`). **삽입 전 반드시 마스킹된 `#v=` 사용**, 사용자 옵트인 체크박스로 링크 삽입 여부 선택(기본 켜짐, 수치 노출 경고 포함).
3. IC PPT 마지막 장에 QR(`#v=…&src=ppt`) + "휴대폰으로 이 모델 열기". PNG 카드 QR 옵션(`&src=png`).
4. 읽기 전용 착지 하단에 고정 CTA 바: **"이 가정으로 내 딜 시작하기"** → `__mtExitReadonly()` 후 편집 모드 + `mtTrack('recover_cta')`.

**파리티·불변 영향:** 계산 무관. **불변 주의:** 링크에 실릴 수 있는 딜 수치는 `#v=` 읽기전용+임차인 마스킹 경로만 사용. 옵트인 없는 자동 삽입 금지. `src` 값은 채널명 화이트리스트만(자유 문자열 금지).

**검증 계획:** Playwright — 엑셀 커버 하이퍼링크가 `#v=`+`src=xlsx` 포함·수치 미포함(마스킹 확인), PPT/PNG QR 디코드=링크(jsQR 재사용), 착지 CTA 클릭→편집 전환. CI 마커: 옵트인 체크박스·`src=` 파싱. 파리티 재검증(엑셀 커버 시트 변경 → 4딜 gen-xlsx + check.py).

**수용 기준:** ☐ 4종 산출물 전부에 회수 링크·QR ☐ 전부 `&src=` 태그 ☐ 마스킹 자동 적용 + 옵트인 ☐ 착지 하단 CTA 동작 ☐ 파리티 유지.

**규모·리스크:** M. 리스크: 엑셀 하이퍼링크가 수신자 눈에 딜 수치를 링크로 노출 → 옵트인+마스킹으로 차단, 경고 문구 필수.

**하지 말 것:** 옵트인 없는 수치 링크 자동 삽입, 이메일·연락처 수집, `src`에 채널명 외 값.

### E4 · 팀 기준 배포 링크(#h=) — 하우스 기준의 팀 표준화

**배경·목표**
스토리: *팀장(챔피언)이 심사 기준(허들 IRR·DSCR·표준 부대비·기본값)을 링크 하나로 팀 전체 브라우저에 설치한다.* 팀원 모델이 같은 잣대로 계산되고 산출물에 "OO팀 기준 v2 적용"이 표기되어, **개인 발견 → 팀 표준 채택**으로 번지고 시니어의 "분석가마다 가정이 다르다" 불신이 해소된다.

**현재 코드 기준점 (실증)**
- 하우스 기준: `houseLoad()`/`housePop()`, `localStorage('mt_house')`={irr,dscr,ltv}. **개인 브라우저 한정, 공유 수단 없음**(`#h=` 0건 확인).
- 내 기본값: `mt_mydef`(딜 유형별 부대비·보수·대출), `myDefApply()`.
- 인코더 재사용 가능: `mtLZ.compress`/`decompress`(공유 링크와 동일).

**구현 설계**
1. `#h=` 내보내기: 하우스 기준(`mt_house`) + 선택적 내 기본값(`mt_mydef`) + 팀명·기준일·작성자를 `mtLZ`로 압축 → `location.origin+'#h='+enc`. `housePop()` 에 "팀에 배포(링크 복사)" 버튼.
2. `#h=` 가져오기: `tryRestoreFromURL` 에 `#h=` 분기 추가 → **미리보기 모달**(무엇이 설치되는지 표) → "적용" 클릭 시 `mt_house`/`mt_mydef` 설치 + `house_apply` 이벤트. 자동 적용 금지(미리보기 필수).
3. 산출물 표기: 하우스 기준이 설정돼 있으면 검토 메모·PNG·엑셀 자가검증 시트·PPT에 "OO팀 기준 vN 적용" 자동 표기(팀명·기준일). 판정 리드에도 이미 `사내 기준` 표기됨 — 팀명으로 격상.
4. 기준 이탈 입력 배지: 입력이 하우스 기준 범위를 벗어나면 필드에 배지(E?의 가정 점검과 연동).

**파리티·불변 영향:** 계산 무관(기준은 판정·표기용). **불변 주의:** `#h=` 에는 **회사 표준 파라미터만**(부대비율·허들 등), 개별 딜 수치·임차인 정보 절대 불포함. 서버 미경유(링크 안에만).

**검증 계획:** Playwright — 기준 설정→`#h=` 내보내기→새 컨텍스트에서 가져오기 미리보기→적용→`mt_house` 일치, 산출물 표기 반영. CI 마커: `#h=` 파싱·미리보기·`house_share`/`house_apply`. 파리티 불필요(단 산출물 표기가 엑셀 시트 건드리면 파리티 재검증).

**수용 기준:** ☐ `#h=` 내보내기/미리보기/적용 왕복 ☐ 개별 딜 수치 불포함(검증) ☐ 4산출물에 팀 기준 표기 ☐ 자동 적용 없이 미리보기 강제.

**규모·리스크:** M. 리스크: 팀원이 모르고 덮어씀 → 미리보기+되돌리기.

**하지 말 것:** 서버 저장·실시간 동기화·계정, 팀 관리 콘솔, `#h=`에 딜 수치.

- 참고 칩: 폼 필드 아래 `f-ref` 로 렌더. 가정 점검(`checkAssumptions`/`refRange`)이 이 범위를 파싱해 사용.

**구현 설계**
1. `data/market-ref.json` 신규 — 필드별 {값·범위·출처·기준일}. 커밋 타임 스크립트가 `FIELD_REF` 블록으로 인라인(런타임 fetch 0, 무네트워크 동작 유지).
2. 참고 칩에 기준일·출처 뱃지(예: "참고 4~6% · 2026.2Q 한국은행"). 툴팁에 출처 링크.
3. CI: 기준일 6개월 초과 시 경보(하드 게이트 아님, 갱신 리마인더).
4. 출처는 **공개 통계 인용만**(한국은행·국토부·감정원 등), 시세·밸류에이션 제공 아님("개별 자산별 상이" 문구 동반).

**파리티·불변 영향:** 참고치는 판정·점검용, 엔진 계산과 무관(파리티 무영향). 런타임 외부 fetch 금지(무네트워크 유지) — 커밋 타임 인라인만.

**검증 계획:** Playwright — 참고 칩에 기준일·출처 표기, `refRange` 파싱이 새 포맷에서도 동작(가정 점검 회귀 없음). CI: 데이터셋 스키마·기준일 경보. 파리티 불필요.

**수용 기준:** ☐ 참고치가 데이터셋 유래 ☐ 칩에 기준일·출처 ☐ 런타임 fetch 0 ☐ 가정 점검 회귀 없음 ☐ 공개 통계 인용만.

**규모·리스크:** S~M. 리스크: 시세 제공 오해 → "참고·개별 상이" 문구 필수.

**하지 말 것:** 런타임 외부 API fetch, 시세·밸류에이션 포지셔닝, 익명 가정 벤치마크.

### E8 · 분기 시장 노트 — 데이터셋 동기화 콘텐츠 퍼널

**배경·목표**
스토리: *분기 시장 수치를 검색한 실무자가, 그 수치가 사전 입력된 라이브 모델에 클릭 한 번(가입·데모 없이 30초)으로 착지한다.* 시의성 콘텐츠를 SEO·재방문 자산으로 축적하되 E7 데이터셋 갱신과 한 몸으로 돌려 유지비를 최소화.

**현재 코드 기준점 (실증)**
- E7의 `data/market-ref.json`(기준일·출처) — 노트는 이 데이터셋에서 생성.
- 공유 링크 사전 입력: `#v=` 에 특정 가정을 담아 착지 시 자동 반영(`applySharedPayload`).
- sitemap·JSON-LD 패턴은 guide/howto에 존재.

**구현 설계**
1. `notes/YYYYqN.html` — E7 데이터셋에서 생성(분기 수치 + 해설). 수치별로 **사전 입력 공유 링크**(`#v=…&src=notes`) 내장 → 클릭 시 그 가정이 채워진 계산기로.
2. sitemap·JSON-LD(`Article`) 갱신. "투자 권유 아님" 문구.
3. 분기 **1회 상한**(격주 금지). 유입 효과는 E5 계기판(`refHost`·`src=notes`)으로 검증.

**파리티·불변 영향:** 없음(독립 정적 + `#v=` 읽기전용 링크는 마스킹 경로).

**검증 계획:** Playwright — 노트 렌더·사전 입력 링크 클릭→가정 반영·`src=notes` 이벤트. 파리티 불필요.

**수용 기준:** ☐ 노트가 데이터셋에서 생성 ☐ 수치별 사전 입력 링크 동작 ☐ sitemap·JSON-LD ☐ 분기 1회 ☐ E5로 유입 측정.

**규모·리스크:** S(분기 반나절). 리스크: 소속사 컴플라이언스(외부 발행) → 대량 배포 전 확인.

**하지 말 것:** 격주 발행, 커뮤니티·링크드인 대량 배포(컴플라이언스 확인 전), 앱 본체에 콘텐츠 포함.

## 4. 우선순위 시퀀스 & 데이터 게이트

```
1) E5 (계기판·가짜 문)   ← 최우선. 이후 모든 효과의 측정 토대. src 태그 인프라 여기서 확정.
2) E1 (신뢰 센터)         ← 도입 첫 관문. 저비용·독립 문서. E5의 src 필드표와 함께.
3) E2 (산출물 회수 루프)  ← E5의 src 태그 위에 배선. 즉시 유통 효과.
4) E4 (팀 기준 #h=)       ← 전파. 기존 인코더 재사용, 저비용.
5) E3 (검색 착지 30+)     ← 복리 자산. 지금 심어야 6개월 후 수확. 양이 많으니 분할.
── 여기서 첫 데이터 리뷰(E5 스냅샷 2~3회분) ──
6) E6 (재현성·파리티 공표) ← 신뢰 심화. 감사 대응.
7) E7 (참고치 v3)         ← 데이터 격상. E8의 전제.
8) E8 (분기 시장 노트)    ← E7 데이터셋에서 파생. 분기 1회.
```

**데이터 게이트 (E5 스냅샷 누적 후 판단):**
- 모바일 비중 높음 → E2(회수 링크)·PWA·모바일 착지 우선.
- output 전환 낮음 → E1·E6(신뢰) 우선.
- 특정 `src` 채널만 전환 → 그 채널(E3 검색 vs E2 산출물)에 집중.
- `deal_want` 특정 딜 유형 집중 → **그때 비로소** 커버리지(딜 확장) 착수 검토.
- 어느 채널도 전환 없음 → 유통이 아니라 **온보딩·활성화** 재점검(제품 문제).
