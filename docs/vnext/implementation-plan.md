# vNext 구현 계획 — 작업지시서의 비판적 수용 (2026-07-10)

작업지시서 "Institutional Underwriting Readiness"를 **그대로 따르지 않고**, `current-state-map.md`(코드 사실 감사)와
현행 운영 전략(`docs/STRATEGY.md` — 로그 기반 신규 기능 투자 동결, 판독일 07-24)에 대조해 선별했다.

판단 기준 3가지:
1. **정확성·정직성 결함은 즉시** — 사용자가 숫자를 믿게 만드는 도구에서 "조용히 틀리는 것"이 최우선 결함.
2. **대형 기능(월별 리스 엔진·Debt 2.0·워터폴 2.0·IndexedDB)은 수요 증거 후** — 로그 판독(07-24)과 사용자 수요 신호 전에는 착수하지 않는다(전략 원칙: 데이터 전 선제 구현 금지). 단일 파일·성능 예산(gzip<300KB) 구조와도 충돌.
3. **지시서의 사실 오인은 기각 사유로 기록** — 예: 개발 IRR은 "가짜 IRR"이 아니라 2점 현금흐름 가정의 정확한 IRR.

## 롤백

- 이번 배치는 전부 단일 커밋 계열(PR) — `git revert`로 전체 원복 가능.
- NOI 역산은 `assumOverrides` 말미 블록 하나 — 블록 제거 시 이전 동작(직접 입력 무시)으로 복귀. 캐시는 함수 프로퍼티라 상태 잔존 없음.
- stepUp 정규화는 `normStepUp` 한 함수 — 제거 시 원시값 소비로 복귀.
- 공유·모달·문구는 표시 전용 — 엔진·엑셀 비접촉(파리티로 증명).
