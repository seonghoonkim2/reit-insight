# 저장소 마이그레이션 계획 (보류 — 설계만 보존)

작업지시서 Phase 9(IndexedDB)는 **이번 사이클에서 실행하지 않는다.** 근거와, 실행할 때의 설계를 남긴다.

## 왜 지금 안 하나

- 현재 localStorage 사용: 딜 보관함(`mt_deals` — 입력 스냅샷·버전 배열), 개인 기본값(`mt_mydef_*`), 하우스 기준, 설정 플래그 몇 개. **렌트롤 원본은 원칙적으로 저장하지 않으므로**(임차인명도 확정 시점에 제거) 용량 압박의 주범이 없다.
- 실측: 예시 딜 수십 개 저장해도 수백 KB 수준 — localStorage 한도(~5MB)까지 여유.
- 마이그레이션은 그 자체가 최대 리스크(기존 딜 유실·이중 상태). 편익(용량·트랜잭션)이 실재하는 사용자가 없는 동안은 순риск.
- **트리거**: ① 사용자 저장 실패(QuotaExceededError) 리포트 1건 ② 월별 상세 데이터 저장 기능이 실제로 채택될 때 ③ 버전 스냅샷 평균 크기 급증.

## 실행 시 설계 (지시서 15.1~15.2 수용)

1. 스토어: `deals`(현 mt_deals 구조 그대로) · `defaults` · `settings` · `migrationLog`.
2. 절차: 부팅 시 IndexedDB 미존재 → localStorage에서 읽어 IndexedDB에 기록 → **읽기 검증(개수·해시 대조) 성공 후에만** localStorage 원본에 `migrated=1` 마킹(삭제는 그 다음 릴리스에서).
3. 롤백: IndexedDB 열기 실패·검증 실패 시 localStorage 경로로 자동 폴백(코드 경로 유지).
4. `.modelter` 파일(schema '1.0') import는 저장 백엔드와 무관하게 유지 — 스키마 버전 필드로 상위 호환.
5. 공유 링크(#v/#e)는 저장소와 무관 — 영향 없음.
6. 마이그레이션 텔레메트리는 성공/실패 이벤트명만(개인 데이터·건수 없음) — `/e` 불변 원칙 유지, `docs/METRICS.md` 사전 등재 후.
