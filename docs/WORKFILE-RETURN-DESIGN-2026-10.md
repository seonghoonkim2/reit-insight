## 지원 후보와 제외 범위

첫 구현 후보는 **활성 렌트롤을 쓰지 않는 오피스·물류센터 표준 매입**으로 제한한다. Excel에서 수정 가능하다는 사실만으로 웹 재가져오기도 지원하는 것은 아니다.

| 딜/파일 유형 | 첫 구현 후보 | 제외하거나 이후 별도로 설계할 항목 |
|---|---|---|
| 표준 매입, 임대료 방식 | 매입가와 연결된 감정가, 임대료·관리비·공실·수입 상승률, Exit Cap, 기존 선순위 차입조건, 보유기간 | 임대방식 전환, 면적·세금·운영비·보증금 구조·우선주·중순위·시나리오의 수정. 처음에는 생성 시점 그대로여야 한다. |
| 표준 매입, 직접 NOI 방식 | 매입가와 연결된 감정가, 연 NOI·NOI 상승률, Exit Cap, 기존 선순위 차입조건, 보유기간 | 임대료 방식으로 전환, NOI의 세부 수입·비용 분해, 임차보증금 등 지원 목록 밖의 수정. |
| 활성 렌트롤 매입 | 첫 구현에서 받지 않는다. | 임차인·계약 행, 시장 가정, 임차인 그룹, 기간 변경. 단순 A&R 숫자로 덮으면 계약별 계산 경로가 달라진다. |
| 참고용 Rent Roll이 붙은 표준 매입 | 표준 가정만 후보로 둔다. | 참고용 계약표 수정값은 수익률에 연결되지 않는다. 계약표 변경이 있으면 자동 적용하지 않고 미지원 변경으로 알린다. |
| 공동주택 개발 | 첫 구현에서 받지 않는다. | 월별 공정·분양·토지대금·금융 스케줄과 세대형별 입력은 별도 매핑·월별 파리티 설계가 필요하다. Excel에서 편집 가능한 사업비도 첫 범위에서는 가져오지 않는다. |
| 리파이낸싱 | 첫 구현에서 받지 않는다. | 새 대출 대안별 금액·금리·기간·상환방식과 기존 대출 참고 항목의 역할이 달라 별도 설계가 필요하다. |

지원하지 않는 딜이나 활성 렌트롤 파일을 선택하면 현재 화면을 바꾸지 않고 이유를 표시한다. 현재 화면이 활성 렌트롤·다른 딜 유형이면 그 화면에 표준 매입 가정만 섞어 넣지 않는다. 현재 화면이 활성 렌트롤·다른 딜 유형인 경우에는 적격 파일을 새 딜로 여는 선택만 제공한다.

## 매핑과 단위 계약

다음은 현 A&R의 위치를 근거로 한 첫 매핑안이다. 실제 기능은 셀 주소만 추측하지 않고, 파일의 명시적 형식 버전과 필드 식별자에 맞는 매핑을 선택해야 한다. 읽을 때 화면에 표시된 반올림 문자열이 아닌 셀의 원시 숫자를 쓴다. 퍼센트는 Excel 비율값과 웹의 퍼센트 숫자를 구분하며, 빈칸을 0으로 바꾸지 않는다.

| Excel 입력/조건 | 웹 입력 후보 | 변환·검증 |
|---|---|---|
| `A&R!C11`, 생성 시점 `C7` | `state.price` | C11은 만원/평, C7은 평이다. 총매입가(백만원) = C11×C7÷100. C7은 양수이며 변경되지 않아야 한다. 계산 셀 C12를 입력값으로 가져오지 않는다. |
| `A&R!C13`, 위 매입가 | `state.appraisal` | C13은 감정가/매입가 비율이다. 감정가(백만원) = 비율×변경 후 매입가. 매입가 변경 시 영향받는 감정가도 비교표에 표시하고 함께 적용한다. 기존 감정가를 그대로 두어 LTV 대출액이 어긋나게 하지 않는다. |
| `C23`, `C24`, `C25` | `rentpp`, `campp`, `vacancy` | 임대료·관리비는 원/평·월. C25는 점유율이므로 웹 공실률(%) = (1−C25)×100. 임대료 방식에서만 적용한다. |
| `C27`, `C28` | `noig` | 웹에서는 수입 상승률 하나가 두 셀에 들어간다. 두 비율이 같을 때만 ×100으로 가져온다. 서로 다르면 평균하거나 한쪽을 고르지 않고 거부한다. |
| `C90`, `C91`, `C92` | `noimode`, `noi1`, `noig` | C90 모드는 생성 시점과 같아야 한다. 직접 NOI에서만 C91 연 NOI(백만원), C92 비율×100을 적용한다. 연 NOI는 0·적자도 허용하며 기존 엔진 검증을 따른다. C90을 바꾸는 방식 전환은 제외한다. |
| `C58` | `exitcap` | Excel 비율×100. 유한한 양수이며 기존 입력 범위를 통과해야 한다. |
| `C45`, `C46` | `stackState.senior_ltv/rate` | 비율×100. 기존 선순위 포함 여부는 유지한다. 꺼진 대출의 LTV를 파일에서 늘려 자동 활성화하지 않는다. |
| `C47`, `C48`, `C80` | `senior_extra`, `state.maturity`, `senior_grace` | 상환방식은 허용된 문자열을 정확히 대응한다. 만기일시(이자만)/원금균등/원리금균등/거치후 원리금균등 외 값은 거부한다. 기간은 정수이며 상환방식·거치기간의 기존 조건도 검증한다. |
| `C79` | `hold` | 표준 매입의 3~10년 정수만 허용한다. 반올림·범위 강제 보정 없이 잘못된 입력을 거부한다. 활성 렌트롤 고정 기간 파일은 이 경로 대상이 아니다. |

의존 항목은 하나의 적용 묶음이다. 예를 들어 매입가·감정가 비율·LTV가 서로 영향을 주면 비교표는 바뀌는 총매입가·감정가·대출액을 함께 보여준다. 선순위 조건은 포함 여부와 상환방식·만기·거치를 함께 검증한다. 묶음 일부만 선택해 의미가 달라지는 경우에는 선택을 막고 이유를 표시한다.

지원 목록 밖의 계산 관련 입력이 바뀌면 나머지 지원값만 조용히 가져오지 않는다. 첫 구현은 해당 파일의 적용을 중단하고 변경된 항목을 열거한다. 단순 서식·열 너비·줌·메모 등 계산에 영향이 없는 변경은 허용할 수 있지만, 이름·URL·메모 내용 자체를 가져오거나 이벤트에 기록하지 않는다.

## 파일 식별과 무결성

새 가져오기 형식에는 최소한 `formatVersion`, 모델터 빌드, 딜 유형, 계산 경로(표준/직접 NOI/활성 렌트롤), 필드 식별자·셀 주소·단위·자료형, 생성 시점 입력 스냅샷, 지원 입력 목록, 수식·계산 관련 비지원 입력의 비교 기준이 필요하다. 이것은 새 형식의 설계이며 현재 `_Restore`에 모두 존재한다는 뜻이 아니다.

- 알 수 없는 형식 버전, 필수 메타데이터가 없는 구형 파일, 삭제·중복 시트/필드, 손상된 ZIP/XML, 암호화 파일, 매크로 파일은 거부한다. 구형 파일은 기존 ‘다운로드 원본 복원’과 구분해 안내한다. 수정값 가져오기 실패 뒤 원본 스냅샷을 대신 적용하지 않는다.
- ZIP의 STORE·DEFLATE와 공유 문자열 등 일반적인 XLSX 재저장 형태를 읽어야 한다. 현재의 평문 마커 검색을 수정 파일 파서로 재사용하지 않는다. 외부 참조·DDE·매크로·XML 외부 엔티티·사용자 수식은 실행하거나 네트워크로 해석하지 않는다.
- 가져오기 대상은 숫자와 명시적으로 허용한 상환방식 입력이다. 지원 입력 셀에 수식을 넣은 경우, 수식 셀 변경, 행·열 이동, 참조 구조 변경, 계산 관련 시트 삭제는 거부한다. Excel 캐시 결과를 웹의 참값으로 채택하지 않는다. 셀 형식만으로 단위를 추정하지 않는다.
- 서식과 계산 구조를 구분해 검사한다. 재저장에 따른 ZIP 순서·압축·XML 직렬화 차이는 계산 변경이 아니다. 수식 비교는 검증된 형식의 의미를 보존하는 제한된 정규화만 허용하고, 알 수 없는 변환을 넓게 허용하지 않는다.
- 로컬 해시/비교값은 실수나 구조 변경 탐지용이다. 파일을 고친 사람이 메타데이터도 바꿀 수 있으므로 발급자의 전자서명이나 위변조 증명이라고 표시하지 않는다. 알려진 형식, 허용 필드, 현재 엔진 재계산으로 신뢰 범위를 제한한다.
- 초기 파일 처리 상한안은 압축 10MiB, 압축 해제 합계 50MiB, ZIP 항목 256개다. 이를 넘으면 화면 상태를 바꾸기 전에 중단한다. 구현 시 모델터 최대 지원 파일과 브라우저 메모리·성능 검사로 상한을 확인하며 자동 상향하지 않는다. 새 CDN·패키지 의존성을 도입하지 않고 현재 단일 파일·성능 예산 안에서 가능한지 먼저 판정한다. 불가능하면 미구현 상태를 유지한다.

## 적용 전 비교와 저장 절차

1. 파일은 브라우저 메모리에서 읽고 검증한다. 현재 딜, 선택 버전, 미저장 수정, 시나리오, 출처, 예시 상태와 로컬 저장소를 변경하지 않는다. 읽기 전용 화면에서는 자기 모델로 전환하기 전 적용할 수 없다.
2. 검증을 통과하면 파일 유형·생성 빌드·생성 시점과 기준 스냅샷을 표시한다. 현재 작업과 동일 딜인지 ID만으로 단정하지 않는다. 내보낸 뒤 웹에서도 수정했다면 생성 시점→Excel과 생성 시점→현재 화면을 나눠 충돌로 표시한다.
3. 비교표는 ‘항목 / 단위 / 생성 시점 / Excel 수정값 / 현재 화면 / 적용 여부’를 가진다. 지원되지 않는 변경과 자동으로 함께 달라지는 항목은 별도 표시한다. IRR·DSCR 변화는 기존 엔진으로 계산한 미리보기이며 입력값과 구분한다. 0과 빈칸, 미정의 결과와 0을 구분한다.
4. 허용된 항목 묶음만 사용자가 선택한다. 기본 적용 대상은 새 딜이다. 같은 저장 딜의 새 버전으로 적용하려면 해당 딜·현재 버전·미저장 상태를 다시 확인하고 충돌 항목을 명시적으로 선택하게 한다. 기존 버전을 덮어쓰는 선택은 제공하지 않는다. 활성 렌트롤이나 다른 딜 유형에 덧씌우기는 금지한다.
5. 적용 전 현재 작업을 `.modelter`로 백업할 수 있게 한다. 백업 취소·실패를 완료로 표시하지 않는다. 기존 저장 딜로 적용할 때 현재 미저장 초안도 보전할 수 있어야 하며, 사용자가 현재 작업 보관을 취소하면 가져오기도 중단한다. 적용을 취소하거나 창을 닫으면 입력·선택 버전·저장값이 그대로다.
6. 확인한 기준 해시와 현재 작업이 여전히 같은지 적용 직전에 다시 확인한다. 다르면 오래된 비교표를 적용하지 않고 다시 비교한다. 입력 후보를 깊은 복사본에 적용하고 기존 검증·계산 함수를 호출한다. 기존 허용 경계를 벗어나거나 계산이 실패하면 실제 상태에 반영하지 않는다.
7. 성공할 때만 새 딜 또는 새 버전을 한 번 저장한다. 저장 공간 부족, 직렬화 실패, 번호 한도, 예외가 나면 입력·렌트롤·시나리오·출처·예시 상태·WS 연결·딜 이력·최대 버전 번호와 로컬 키를 이전 상태로 되돌린다. 두 로컬 키를 원자적으로 쓰는 기능이 없으므로 사전 백업과 실패 후 복원·재시작 복구를 별도 검증해야 한다. 복원 자체가 실패하면 성공 토스트를 띄우지 않고 메모리의 이전 작업 백업을 제공한다.
8. 적용 완료 후 항목 수와 새 딜/버전만 안내하고 재계산 결과를 보여준다. Excel 원본 파일을 저장하지 않는다. 선택하지 않은 입력과 기존 출처·기준일을 보존한다. 바꾼 필드의 출처는 기존 출처를 새 수치의 검증 근거처럼 유지하지 말고 ‘Excel 수정값’임을 로컬 비교 기록으로 구분한다. 현 출처 선택지에 새 값을 자동 추가하는 변경은 별도 명세 없이 하지 않는다.

## 개인정보와 계측

파일·딜 숫자·입력값·원본 임차인명·파일명·로컬 경로·URL·메모·예외에 포함된 셀 내용은 서버로 보내지 않는다. 지원 범위에 임차인명 가져오기는 없다. 익명 렌트롤도 이번 수정값 적용에서 제외하며 기존 그룹 마스킹을 훼손하지 않는다. 원본 파일은 처리 후 참조를 해제하고 영구 보관하지 않는다.

현재 `xlsx_restore`는 생성 시점 원본 복원 이벤트다. 새 기능의 성공을 여기에 섞어 역사적 의미를 바꾸지 않는다. 구현 시 계측이 필요하면 개인정보 없는 제한된 상태만 별도 명세하고 `METRICS.md`·`/trust`·Worker 허용 목록과 CI의 일치를 먼저 갖춘다. 이 설계 단계에서는 이벤트나 전송 필드를 추가하지 않는다.
