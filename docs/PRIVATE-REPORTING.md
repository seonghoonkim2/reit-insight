# 상세 사용 통계 비공개 전환

2026-10-22 · 운영 사이트 배포와 수집 전환은 별도 확인 후 진행한다.

## 보관과 권한

- 대상은 `seonghoonkim2/modelter-usage-reports` 비공개 저장소다. 공개 소스 저장소의 Actions 파일·실행 요약은 비공개 보관 수단이 아니다.
- 상세 조회는 비공개 저장소에서만 실행한다. 새 수집 작업은 공개 저장소에 통계 JSON·HTML·실행 요약을 쓰지 않는다.
- 보고서는 Actions artifact로 90일 보관한다. 보고서 자체는 Git에 커밋하지 않는다.
- 조회 토큰은 대상 Cloudflare 계정의 Analytics 읽기 권한만 사용한다. `CF_ACCOUNT_ID`, `CF_API_TOKEN`을 비공개 저장소 Actions secrets에 등록하며 문서·채팅·소스·실행 출력에 값을 남기지 않는다.
- 기존 GitHub secret은 읽어 옮길 수 없다. 새 조회 권한을 준비해야 한다. 로컬에서 얻은 운영 집계도 공개 저장소에 커밋하지 않는다.

## 배포 준비와 전환 순서

1. 비공개 저장소의 보고서·라벨·과거 보고서 렌더러, `validate-report.js`, 회귀 검사와 수집 workflow를 같은 검증 버전으로 동기화한다. `source-manifest.json`에 소스 커밋과 파일 해시를 남긴다.
2. `Verify reporting code`가 통과하고 비로그인 조회가 404, 권한 있는 조회가 200인지 확인한다.
3. 조회 전용 secrets를 등록한 뒤 `Modelter private usage report`를 수동 실행한다. `end_date`는 제외되는 한국 시간 날짜이며 기본값은 오늘이다. 최근 완료 30일 및 서로 겹치지 않는 두 7일 창을 사용한다.
4. JSON의 기간·가중합·자료 상태를 확인하고 `node tools/private-reporting/validate-report.js reports/patterns.json`으로 엄격한 전환 검증을 실행한다. 기본 모드는 모든 `partial` 자료를 거부한다. 같은 절대기간의 기존 조회와 총계를 대조한다. 실패·누락·접근 불가는 0건이 아니다.
5. 비공개 저장소 변수 `REPORTS_ENABLED=true`를 설정하고 다음 예약 실행의 성공을 확인한다. 준비 전에는 예약 수집을 켜지 않는다.
6. 위 완료 증거와 배포 승인을 받은 뒤 공개 patterns/snapshot/doctor workflow의 상세 조회를 종료한다. 전환 직전 실행 중인 공개 수집 작업과 미병합 자동 스냅샷 PR·자동 병합 예약을 확인하고, 이전 수집이 새 공개 자료를 쓰지 않는 상태까지 확인한다. 이 PR의 교체 workflow는 상태 안내만 출력한다. 이전 공개 JSON은 당시 UTC/rolling 기간 정의를 유지한 과거 자료로 동결한다. 과거 공개 이력을 회수했다고 표현하지 않는다.
7. 월요일 08:50 KST 분석은 비공개 저장소 최신 성공 보고서의 자료 상태를 먼저 읽는다. `partial`은 표본 차이가 있는 진단 자료로만 사용하고 차이와 해석 한계를 밝힌다. 전환 전·수집 지연이면 마지막 사용 가능한 자료의 실제 종료일을 밝힌다. 오래된 공개 자료로 새 비공개 수집 성공을 대신하지 않는다.

## 기간과 해석

같은 날짜가 포함된 여러 보고서를 더하지 않는다. 필요한 기간을 한 번 조회하거나 일별 기간 키로 중복을 제거한다. 방문은 페이지 실행 횟수이며 사람 수가 아니다. `xlsx_ready`는 파일 바이트 생성 완료, `wizard_finish`는 마지막 화면 도달이다. `resume_copy`와 `src=resume` 착지는 서로 연결된 개인의 이동 기록이 아니다.

Analytics Engine의 [공식 보존기간은 3개월](https://developers.cloudflare.com/analytics/analytics-engine/limits/#data-retention)이며 모든 날짜의 정확한 90일 보존을 보장하는 의미가 아니다. 선택 기간이나 두 비교 기간의 시작이 수집 시점의 90일 경계보다 오래되면 조회를 거부하고 `unavailable` 및 `null` 수치로 남긴다. 이전 성공 HTML·JSON도 실패 상태로 교체한다. 기본 30일 보고서와 별도로 표시하는 관심 유형 90일 집계는 조회 가능한 기록에 한정하며 전체 누적으로 해석하지 않는다.

예약 수집은 `--allow-sampling-difference`를 사용한다. 모든 조회가 정상이고 보존·기간·숫자 검사에 문제가 없으며 실제 차이와 `availability.reconciliation` 기록이 일치할 때만 표본 차이가 있는 `partial` 보고서를 진단용으로 보관한다. 서로 다른 SQL 조회의 가중합을 강제로 맞추지 않는다. 같은 원본을 나눈 일별·시간대·요일 합계의 차이, 누락 쿼리, 행 제한, 잘못된 기간, 검증용 fixture는 이 모드에서도 실패한다. 예약 실행 성공은 비공개 전환의 엄격한 검증을 대신하지 않는다.

## 현재 이행 상태

비공개 저장소와 코드 준비 단계다. 조회 인증정보 등록·실데이터 수집·예약 성공·같은 기간 총계 대조 전에는 이행 완료나 공개 수집 중단을 선언하지 않는다. 계정 연결과 배포 승인 대기는 사용자 확인 사항으로 남긴다.
