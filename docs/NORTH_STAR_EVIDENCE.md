# 북극성 검증 기록 규칙

목표는 방문량이 아니라, 한국 CRE 팀에서 딜 검토를 시작할 때 모델터가 먼저 떠오르는지 확인하는 것이다.
검증 문장은 팀 안에서 **“이거 모델터로 돌려봤어?”**가 자연스럽게 나오는 상태다.

## 현재 상태 — 첫 배포 후 기준선

2026-08-15 11:39:44 KST 스냅샷 기준으로 아직 **판정 보류**다. 팀 전달 실험창의 방문 10건 중 자기 숫자 입력은 1건(10.0%), 첫 자기 딜 결과는 5분 이내 1건이며, 실사용 공유 메뉴와 실제 링크는 각각 0건이다. 예시→내 딜 CTA 배포 후 별도 창은 방문 1건, CTA·자기 숫자 입력·첫 결과가 모두 0건이다.

이 수치는 목표 달성이나 실패의 증거가 아니라, 배포 직후의 작은 시작 표본이다. 최초 기준선은 [`939d285` 시점의 스냅샷](https://github.com/seonghoonkim2/reit-insight/blob/939d285147b51b740c26b0bef27a29331056ef13/data/ae-snapshots/2026-08-15.json)으로 고정한다. 이후 수치는 [`data/ae-snapshots/2026-08-15.json`](../data/ae-snapshots/2026-08-15.json)의 같은 고정 창 필드만 갱신하며, 창이 닫히기 전에 결론을 내리지 않는다.

## 증거로 세는 것

- 서로 다른 실무자 3명 이상이 자발적으로 “IM·티저를 받은 뒤”, “미팅·입찰 전”, “팀에 첫 숫자를 올리기 전” 같은 실제 시작 순간을 설명한다.
- 그중 1개 팀 이상에서 모델터 사용 여부를 묻는 표현이나 링크 전달이 반복된다.
- 제품 로그에서는 같은 14일 동안 실사용(`act=1`) `handoff_open` 10건, `share_link` 5건 이상이 확인된다.
- 활성화율은 10% 이상을 유지한다. 팀 전달 수치가 올라도 첫 계산 진입이 무너지면 채택하지 않는다.

기능 요청, “좋다”는 평가, 유도 질문에 대한 동의, 예시 숫자로 만든 공유는 위 증거를 대체하지 못한다.

## 질문 방식

먼저 답을 암시하지 않고 아래 세 가지만 묻는다.

1. 최근 어떤 업무 상황에서 모델터를 열었거나 열지 않았나요?
2. 그때 가장 먼저 확인하려던 숫자나 판단은 무엇이었나요?
3. 그 다음 팀 검토는 어떻게 이어졌나요?

“모델터로 돌려봤냐는 말을 들었나요?”처럼 목표 문장을 먼저 보여 주는 질문은 검증에 쓰지 않는다. 부정적 답변과 열지 않은 이유도 그대로 기록한다.

## 현장 확인 절차

1. 서로 다른 CRE 실무자 3명 이상에게 실제 딜 검토가 지나간 뒤 10~15분만 요청한다. 제품 시연이나 목표 문장은 세 질문에 답한 뒤에만 보여 준다.
2. 관찰 단위는 일반적인 호감이나 사용 의향이 아니라 **한 번의 실제 딜 검토 시작 순간**이다. 같은 대화에서 비슷한 말을 여러 번 한 것은 한 건으로만 센다.
3. 같은 사람이 여러 딜에서 반복 사용한 기록은 반복 증거가 될 수 있지만, ‘서로 다른 실무자 3명’ 중 한 명으로만 센다.
4. 팀 언어의 반복은 같은 팀의 서로 다른 딜 시작 순간 2회 이상에서 모델터 사용 여부를 먼저 확인했을 때만 인정한다. 조사자가 목표 문장을 말한 뒤 받은 동의는 세지 않는다.
5. 인터뷰 직후 아래 익명 양식에 일반화한 사실만 적고, 실제 딜명·회사명·수치·인용 원문은 저장소에 넣지 않는다.

제품 하단의 ‘어떤 순간에 열었나요?’ 응답도 같은 세 질문에 대한 비유도형 설명일 때만 질적 증거 후보가 된다. 이메일 회신이나 칭찬만으로는 채택 근거가 되지 않는다.

## 익명 기록 양식

실제 딜명·자산명·수치·임차인명·회사명·개인 이름·연락처는 저장소에 기록하지 않는다. 직접 인용은 별도 동의를 받은 경우에만 쓰고, 기본은 의미를 보존한 요약으로 남긴다.

| 주차 | 역할(일반화) | 시작 순간 | 첫 확인 대상 | 팀에서 이어진 행동 | 반복 사용 증거 | 판정 |
|---|---|---|---|---|---|---|
| YYYY-Www | 운용/투자/대주 등 | PII 없는 요약 | IRR·DSCR·하방 등 | 링크/Excel/구두 검토 등 | 첫 사용/반복/미확인 | 채택/반증/보류 |

## 14일 판정

서로 다른 기능의 실제 프로덕션 배포 완료 시각이 달라 아래처럼 창을 각각 고정한다. 종료 시각은 모두 미만이다.

| 진단 | 고정 창(KST) | 판독 |
|---|---|---|
| 팀 전달 | 2026-08-15 08:03:30 ~ 2026-08-29 08:03:30 | 방문·자기 숫자 입력·실사용 공유 메뉴·실제 링크 |
| 첫 숫자 속도 | 2026-08-15 10:18:30 ~ 2026-08-29 10:18:30 | 첫 자기 딜 결과 5분·15분·30분·초과 구간 |
| 예시→내 딜 | 2026-08-15 11:23:17 ~ 2026-08-29 11:23:17 | 방문·CTA·자기 숫자 입력·첫 결과 진단 |

이 창들이 닫히기 전 수치는 진행 신호일 뿐이며 채택·부분 채택·철회를 확정하지 않는다. 이후 스냅샷도 같은 고정 창만 재조회해 롤링 기간이 앞부분을 자르거나 누적 기간이 늘어나는 오판을 막는다. 예시→내 딜 수치는 CTA를 거치지 않고 바로 입력할 수 있어 엄격한 포함 퍼널이나 별도 성공 기준으로 쓰지 않는다.

- **채택:** 정량 기준과 질적 기준을 모두 충족한다.
- **부분 채택:** 활성화는 유지되고 팀 전달 행동은 생겼지만, 반복되는 팀 언어의 증거가 아직 없다. 메시지는 유지하되 기능 투자는 늘리지 않는다.
- **철회:** 실사용 `handoff_open` 3건 미만이거나 활성화율이 10% 아래로 하락한다. 결과 바로 아래 전달 노출을 되돌리고 원인을 다시 조사한다.
